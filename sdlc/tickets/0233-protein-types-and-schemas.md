# 0233 — Add the protein types and generated schemas

Status: OPEN.

Milestone: 4

Depends on: 0229

## Outcome

`biodata` adopts `UniProtIsoform`, `AminoAcids`, and `UniProtFeature` exactly as the biodata agreement defines them, copies `UncertainSpan0` for feature spans, and adds the error codes `protein.residue.invalid`, `protein.site.order` and `id.uniprot_isoform.invalid`. It holds checked InterPro and Complex Portal accession types and the neutral, no-I/O protein records that `planning/slices/protein.md` names: `ProteinHeader`, `ProteinIsoform`, `ProteinFeature`, `ProteinDomainMatch`, `ProteinComplexHeader`, `ProteinComplexMember` and `ProteinStructureRef`, plus a sequence record with its returned accession and audit metadata and a function record with its source text and evidence. `biomcp-types` holds the consumer side: the `search protein` request with a positional text query or `--gene SYMBOL`, `--reviewed`, `--include-unreviewed` only if 0229 proved its positive, and `--limit`, `--pool` and `--offset` with a default of five and a maximum of 25; the `get protein` request with one or more accessions or a gene symbol, the sections `features`, `domains`, `isoforms`, `complexes`, `structures`, `function`, `sequence` and `all`, and `--section-limit`; the relation requests `protein features ACCESSION` with `--position N` and `--type TYPE`, `protein domains ACCESSION` with `--type TYPE`, `protein isoforms ACCESSION`, `protein complexes ACCESSION`, `protein complex-members ACCESSION --complex CPX-ID`, `protein structures ACCESSION` and `protein sequence ISOFORM`, each page request with `--limit`, `--pool` and `--offset`; the `ProteinCard` and each page. The generated, checked-in schemas are `biomcp.protein_page/1`, `biomcp.protein_card/1`, `biomcp.protein_features/1`, `biomcp.protein_domains/1`, `biomcp.protein_isoforms/1`, `biomcp.protein_complexes/1`, `biomcp.protein_complex_members/1`, `biomcp.protein_structures/1`, `biomcp.protein_sequence/1` and `biomcp.protein_function/1`.

- Why: the slice method lands types and schema before adapters, and the accepted design with the 2026-10-26 protein rulings fixes the records, the command tree and the page shapes.
- Starts from: protein.md's identity, types and schema section, command tree and case table, with the 2026-10-26 protein rulings, which win over the design text; the j14202, j14211 and j14221 captures and 0229's witnesses on the evidence store; `planning/biodata-variants-and-annotations.md` for the shared protein types; `rust-standards.md`; the existing `UniProtAcc`, `Position1` and `Term` types and the gene `Protein` record.
- Rules: `UniProtIsoform` keeps P15056 or P15056-2 as supplied and never appends `-1`. `AminoAcids` holds nonempty uppercase standard residues plus U, O and X. A queried residue is a `Position1`, and a source inclusive start and end become an `UncertainSpan0` with their uncertainty kept. InterPro location groups and fragments stay arrays, including discontinuous ones, and never collapse to one range. Source Domain, Region, Zinc finger and Repeat feature labels stay distinct, and an InterPro family, site, repeat or superfamily never becomes a domain. Member signatures stay distinct from the integrated InterPro entry. Protein and gene names are display fields and never join keys, and a returned gene name never creates an HGNC ID. An isoform with no direct sequence says so, and no sequence is built from another entry. A complex header keeps the native predicted flag literally and the actual participant total, and a non-protein member is a typed source fact with no protein get. A structure reference is a link and claims no residue coverage. A page carries a native total only for its own collection, and a complex search total is never an admitted membership total. Text and `--gene` are exclusive, `--reviewed` with `--include-unreviewed` is a conflict, and a zero position, a zero limit, a limit over 25 and `--position` on `domains` fail before I/O. `--type` on `features` takes UniProt's native feature type label exactly as sent, such as `Domain` or `DNA binding`, with no alias mapping, per the 2026-10-26 PM ruling, and `--type` on `domains` takes InterPro's native type names. There is no STRING type, no `ProteinAssociation`, no `protein associations` request, no `--all-species`, no `--disease` and no `--existence`. The gene `Protein` record and the gene `protein` section schema stay unchanged, and the type review states how `ProteinHeader` shares that record's fields without a second name for one concept.
- Proof: cases first. Type review checks each field's absence, multiplicity and collection scope against the j14202, j14211 and j14221 captures and 0229's witnesses, including the 93-participant complex, the discontinuous InterPro fragments, the External alternative products and the explicit P00533-1. Round-trip tests cover each ID form and each closed set, including refusal of a synthetic `-1`, of residues outside `AminoAcids`, of a malformed InterPro or Complex Portal accession and of each before-I/O failure above. The generated schemas are checked in with snapshot and compatibility checks, and existing schemas stay unchanged. This ticket adds no filter or exact-ID get and makes no provider call; each filter and exact-ID get that later protein tickets add has a known-positive capture through one bounded keyless pm job. No licensed content enters the repo, and replies whose terms bar storage replay from outside the repo. Then make landing-gate runs through pm job.
- Defers: executable help, Markdown parity and the shared request, step and envelope schema versions move to 0245, which registers protein in the shared request.
