## Outcome

`biomcp sync cbioportal-studies` downloads the public `/api/studies?projection=DETAILED` catalog, validates every record's study identity and required fields, keeps every record unfiltered and replaces the local copy atomically with a `biomcp.sync` receipt that names the source revision headers when the source sends them and the acquisition time. A replacement that fails parse, identity, size, quota or transport checks keeps the last accepted copy. `search study TEXT` reads only the stored bundle and returns a five-row page of study headers in stable source order, matching TEXT literally and case-insensitively against the native study ID, name and description. `--cancer-type CODE` keeps only records whose native `cancerTypeId` equals CODE exactly, and combines with TEXT as a conjunction. `--limit`, `--offset` and `--pool` page the result with the bundle revision and every selector bound to the pool. A missing bundle answers with a `sync` step, and a stale bundle answers from its rows labeled stale with a `sync` step.

- Why: the first study question asks which cohort to use, and the 2026-10-26 study rulings accept `search study` and `sync cbioportal-studies` for the metadata catalog.
- Starts from: study.md's command tree, case map, bundle rules and measured disclosure budget, with the 2026-10-26 study rulings, which win over the design text; the j14206 catalog capture and 0207's whole-catalog measurement and cancer-type code list; the shared `sync <bundle>` contract, the stored-only bundle read API and architecture 4.11 and 6.10; the existing `cbioportal` declaration in `crates/biomcp-adapters/src/cbioportal/mod.rs` and `crates/biomcp-adapters/src/registry.rs`; 0210's types.
- Rules: the source-wide `restricted` use for cBioPortal stays, and the bundle never relabels the same data as open. A disabled `cbioportal` source or a disabled `restricted` group skips sync and search before any bundle read, cache read or request. Reads never trigger a sync. Search never rewrites a disease name, repairs a typo, adds a synonym, expands a cancer-type code to descendants or converts it to an OncoTree code. `mixed` stays a literal native code and never expands into cohorts inferred from sample diagnoses. Empty TEXT with no `--cancer-type` fails before I/O. A successful empty search differs from source failure, a disabled source and a missing bundle. A changed selector with a continuation fails locally, and an expired pool offers restart with zero provider requests. The bundle holds catalog metadata only and never a study matrix, archive or participant record. The sync receipt is a summary and never a dump of the 551 records. Next steps follow architecture 6.10: one `get study ID` step per candidate on the page, then the page step, then at most three other steps, with the `sync` step only for an absent or stale bundle.
- Proof: outside-in cases first, watched to fail. The PM accepts the retained 0207 catalog as the sync-contract witness (m6528, ask 1). The one bounded keyless request in j14506 succeeded and logged one attempt, a 549,064-byte body and archive SHA-256 `14914b0fd3610a3b5c7c5e46dd2aa2498d2ac3fca6d5b67a1a80998882b7882a`, but automatic job temporary-file cleanup removed its raw body and receipt before transfer. Its log does not establish a body hash or replace the retained evidence. No replacement request is authorized or needed. Search cases assert known positives from S01 to S20: a native title word and an exact study ID each find their study, case handling holds, and `pan_can_atlas` returns multiple hits across a complete page walk with no gap or duplicate. `--cancer-type brca` finds `brca_tcga_pan_can_atlas_2018`; `--cancer-type difg` finds both `gbm_tcga_pan_can_atlas_2018` and `lgg_tcga_pan_can_atlas_2018` (S06, S07); `--cancer-type mixed` finds `msk_impact_2017` (S20); `--cancer-type BRCA` and an unknown code return a successful zero with the exact code echoed; a text and code conjunction narrows both ways. A fabricated text returns a complete empty page. Paging cases cover the default five, limits of one and the maximum, a terminal page, a changed-selector rejection and an expired pool restart with zero network. Sync cases cover a fresh install, a warm read with zero requests, a revision change, a synthetic partial download, a malformed, oversized or identity-conflicting replacement that keeps the old copy, and concurrent sync ownership. Source cases cover the disabled source and the disabled `restricted` group before cache or network. Recorded 429, 500, timeout and broken-body sync cases assert a failed outcome with source and terms that keeps the old copy. The job measures CLI and MCP output for every five-header page over the whole synced catalog, starting from the design's 210-byte header and 1,013-byte page projections and 0207's whole-catalog projection, and each case gets a ceiling at measured size plus 15 percent, recorded in study.md. Real catalog rows fall under the restricted cBioPortal terms, so they replay from outside the repo through `--cases DIR`, and synthetic files prove sync mechanics. No licensed content enters the repo. Then make landing-gate runs through pm job.
