# 0182 — Search VAERS report summaries for MMR, COVID-19 and influenza through CDC WONDER

Status: OPEN.

Milestone: 3

Depends on: 0161

## Outcome

`search adverse-event --source vaers MMR` returns CDC WONDER's VAERS summary for that vaccine: the native total and the first page of native symptom rows with counts, with `seriousness` and `age` sections that each send one more request. The positional text must be one of three supported vaccines, MMR, COVID-19 or influenza, given as WONDER's native code (`MMR`, `COVID19`, `FLU`) or that vaccine's display name, matched exactly without case; any other text fails before I/O and lists the three. Every count is labeled as reports, never people, risk or causation.

- Why: Ian ruled on 2026-10-25 to retry WONDER the way 0.9 did. The retry j13368 returned HTTP 200 and XML aggregate tables for all three MMR groupings (4074 symptom rows, 3 seriousness rows, 14 age rows). 0.9 offered summaries for these three vaccines, and 0.9 is the quality floor.
- Starts from: 0178's ruling and retry recipe; the j13368 evidence in Yellow data/biomcp-redux/0178-wonder-retry/2290-wonder-retry.tar.gz (SHA256 d6aa58b5e05257865544b51ebdeef7861ff65eca014d2c7b65ca82de04ee3f89); 0.9's committed request XML (0.9 commit 4050fdc7, SHA256 5211519efd5d8eb4998681085dd71cd8aaf048d169820f798d7ce5829a2cce66) and its three-vaccine table; adverse-event.md's VAERS interpretation rules and reviewer findings; the FAERS and MAUDE adapters as the pattern.
- Capture first: before shared types are accepted, one bounded keyless pm job sends the same three groupings for `COVID19` and for `FLU` with 0.9's settings: POST as `request_xml=<XML>&accept_datause_restrictions=true`, user agent `Wget/1.21.4`, at least 16 seconds apart, each once, zero retries, redirects or fallbacks, 30-second deadline, 2 MiB cap, archived to Yellow. A vaccine whose capture is denied or empty leaves the supported list, and the PM is told before code continues.
- Rules: the user agent is a per-source registry setting sent only to WONDER; every other source keeps the default. The 16-second gap is a source rate limit in the shared transport, and cached replies are reused. Keep each native table's own total, row labels, codes, counts, percentages, vintage, notices and suppression as sent. Never sum rows into a report total, never use one table's total as another's denominator, and never reconstruct suppressed cells. Symptom rows page with `--limit` and `--offset` over the cached reply with a measured default. VAERS takes no FAERS filter; each one fails before I/O and names the supported route. There is no automatic vaccine detection: FAERS never routes to VAERS and VAERS never routes to FAERS. No individual report get, no CVX name bridge, no free-text vaccine matching. An HTML or denied reply is a failed outcome with source and terms, never zero reports. The registry entry states WONDER's data use restrictions (statistical use only, no re-identification) and their use category; if the category is unclear the developer asks the PM. Help and output say reports do not show that a vaccine caused an event.
- Proof: outside-in cases first, watched to fail, replaying the MMR, COVID-19 and influenza captures from outside the repo if their terms bar storage. Cases assert the native total and symptom page, each section, the symptom page walk with no gap or duplicate, unsupported vaccine text failing before I/O, a FAERS filter on VAERS failing before I/O, and synthetic 403 HTML, 429, 500, timeout and broken XML replies each giving a failed outcome. CLI and MCP outputs are measured and each case gets a ceiling at measured size plus 15 percent, recorded in adverse-event.md. A clinical reviewer checks the wording. No licensed content enters the repo. Then make landing-gate runs through pm job.
- PM ruling 2026-10-25: WONDER's registry use category is `restricted`. Its data are federal, but its data use terms limit use to statistical reporting and analysis and bar re-identification, so a user must read the publisher's terms. The source stays on by default under the standing rule and switches off with the restricted group. Terms name "CDC WONDER data use restrictions" with https://wonder.cdc.gov/datause.html.
- PM ruling 2026-10-25 after capture j13383: the supported list is MMR and COVID-19 only. COVID19 returned tables for all three groupings; FLU returned HTTP 500 with no tables for all three. Influenza text, `FLU` and its display name fail before I/O with "Influenza VAERS summaries are not available yet; supported vaccines are MMR and COVID-19." No query repair or retry here. 0183 looks for WONDER's current influenza code.
- PM ruling 2026-10-25: search adverse-event help ceilings approved at measured +15%: 2925 stdout and 2924 compact bytes (measured 2543/2542 on the branch). The growth comes from the VAERS source, its sections and its noncausation guidance. If the merged measurement differs, the ceiling follows the merged measurement +15% without another ruling.
