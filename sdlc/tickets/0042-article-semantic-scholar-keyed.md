# 0042 — Add Semantic Scholar as a keyed search source

Status: OPEN.

Milestone: 1

## Outcome

`search article … --source …,semantic-scholar` folds Semantic Scholar's relevance order into the pool only when the user's key is configured, resolves its DOI-only rows to PMIDs where a PubMed record carries the same DOI, and without a key skips the source with reason `no_key`, a key step and no request, through the CLI and MCP.

- PM decision: 2026-10-24. `Source::SemanticScholar` spells `semantic-scholar` everywhere. The adapter declares `KeyUse::Required` with `SecretName::SemanticScholarApiKey` in header `x-api-key`, config `keys.semantic_scholar_api_key` and environment `SEMANTIC_SCHOLAR_API_KEY`, and `help key semantic-scholar`. It asks one page of 100 with `fields=externalIds,title,venue,year,publicationDate,authors`. Rows with a PubMed ID key on it. Rows with only a DOI are resolved by one ESearch per 100 DOIs, `A[doi] OR B[doi]`, and each returned PMID is kept only when its ESummary DOI equals the row's DOI without ASCII case; other rows keep the DOI and a header from Semantic Scholar with `types_unknown`. Semantic Scholar applies the words, `--gene` as typed, `--variant`, `--disease`, `--drug` and `--since`/`--until` as `year=A-B`; `--author`, `--journal`, `--type` and `--sort date` are `usage.unsupported_filter` until a checked boundary shows Semantic Scholar's own sort and type filter, which narrows article.md's filter table. `--help` gains the `semantic-scholar` line.
