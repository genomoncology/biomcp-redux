## Outcome

`biomcp sync fda-cdx` downloads FDA's companion diagnostic list page, requires exactly two tables whose ordered headers equal diagnostic.md's two header arrays, including their internal line breaks, keeps every physical row with whole cell text and original links, and replaces the local copy atomically with a `biomcp.sync/2` receipt. Any missing, extra, reordered or changed header in either table fails the whole replacement and keeps the prior usable copy. `search diagnostic --source fda-cdx --device-id P150013` returns that application's rows and `--device-id P150013/S020` only that exact supplement's rows. `--drug-application BLA125514` returns rows whose own drug cell link carries that exact application. `--biomarker KRAS` returns table-0 rows whose whole `Biomarker(s)` cell equals the value. Each search returns a five-row association page with the snapshot revision, table index and physical row index as row provenance, paged with `--limit` and `--offset`.

- Why: 13 of 24 diagnostic questions need device, drug and indication rows that no structured source carries, and the 0154 PM ruling approved this bundle with exact header checks and the recheck amendments fixed its selectors.
- Starts from: diagnostic.md's exact FDA table contract, owned identifier rules, companion page sketch, next-step table and case map, with the 0154 PM rulings and recheck amendments 1, 2 and 3; the j12632 capture's physical tables and resolved rows; the shared `sync <bundle>` contract and stored-only bundle read API; 0172's dispatch registration; 0170's types and 0171's registry.
- Rules: IDs come only from their own cell's standard identifier text and its own link parameter (`ApplNo`, `varApplNo`, PMA `ID`), with a checked grammar. When cell text and link disagree, the row returns an identity problem, keeps the whole cell and offers no pivot. A drug application keeps its published `NDA` or `BLA` type from its own cell and its six digits with any leading zero, and its type is never inferred. A number elsewhere in the row never matches `--drug-application`, and rows without an owned typed drug ID stay reachable by `--device-id`. A combination keeps every therapy, so P200010/S026 keeps `NDA210496` and `BLA125084`. `--biomarker` is whole-cell equality on table 0 only, and on the group table it is unsupported, never a false empty. No cell is parsed into genes, alterations, scores or cutoffs, no row is split into gene and drug edges, and no device name joins GTR or WHO. There is no `--drug-cell` and no card get. Next steps treat the page as an association page under architecture 6.10: one `get drug ID --source drugsfda` pivot per distinct unambiguous owned application in native order, then the page step, then at most three other steps; PMA pivots arrive with 0175; K and DEN numbers stay source links with no get. Reads never trigger a sync.
- Proof: outside-in cases first, watched to fail. Before adapter code, one bounded keyless pm job syncs the bundle once and records the receipt. A sync case asserts 232 table-0 and nine table-1 data rows on the 2026-10-25 capture with both exact header arrays. Device cases assert P190004 (Q01, Q02), P200010/S010 (Q03, Q04), P190026 (Q05), the four P230011 rows (Q07, Q12), the four P140025 rows (Q08), P150013/S020 and P150013/S021 with their distinct scoring context (Q09, Q10), P210001/S001 (Q11) and the ten P200010 rows (Q13). `--drug-application BLA125514` asserts the P150013/S020 row by its owned link, and the P200010/S026 combination asserts both drug pivots. Q06 asserts `--biomarker KRAS` includes P110027/S012 with details G12C, NSCLC tissue context and owned `NDA214665`. Synthetic cases cover a cell and link mismatch, an ambiguous group cell, `--biomarker` on the group table, and a missing, extra, reordered or changed header in each table that fails the whole sync and keeps the prior copy, plus two concurrent readers during one replacement, each labeled synthetic. Each case has a size ceiling from its measured CLI and MCP output, starting from the design's provisional 5,355 bytes for a five-row page. No licensed content enters the repo, and replies whose terms bar storage replay from outside the repo. Then make landing-gate runs through pm job.
