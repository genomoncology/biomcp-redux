# 0210 — Add the study types and generated schemas

Status: OPEN.

Milestone: 4

Depends on: none

## Outcome

`biodata` holds the neutral, no-I/O study records that `planning/slices/study.md` names: a checked opaque `StudyId`, the study header, the study card with its source-stated count metadata, the profile reference, the sample-list metadata and the file reference. `biomcp-types` holds the consumer side: the `search study` request with literal TEXT, `--cancer-type`, `--limit`, `--offset` and `--pool`; the `get study` request with an exact study ID, the sections `profiles`, `sample-lists`, `files` and a bounded `all`, and `--section-limit` and `--section-offset`; the header page, the card and each section page. The generated, checked-in schemas are `biomcp.study_page/1`, `biomcp.study_card/1`, `biomcp.study_profiles/1`, `biomcp.study_sample_lists/1` and `biomcp.study_files/1`.

- Why: the slice method lands types and schema before adapters, and the accepted design with the 2026-10-26 study rulings fixes the records, the command tree and the page shapes.
- Starts from: study.md's shared model boundary, types and identity table, command tree and captured source findings, with the 2026-10-26 study rulings, which win over the design text; the j14206, j14214 and j14223 field and optionality inventories on the evidence store; `rust-standards.md`; the existing checked gene identifier types and the variant recurrence study selector in `crates/biomcp-types/src/query/recurrence.rs`.
- Rules: native study counts stay source-specific metadata. The shared `CohortObservation` subject stays `VariantRef`, and this ticket makes no shared-model change. A `StudyId` is case-sensitive and gets no hyphen or underscore repair. The card keeps `allSampleCount`, `sequencedSampleCount`, `cnaSampleCount`, `structuralVariantCount`, `treatmentCount` and the scoped `resourceCounts` under their native names, and none becomes a denominator or a sample count it is not. An absent patient count stays absent and never reads as zero. Publications keep every PMID, and no scalar PMID field drops a later one. The native cancer-type code keeps its cBioPortal namespace with no uppercase transform and no OncoTree equivalence. `referenceGenome` stays study metadata and never labels a coordinate. A profile reference carries both its exact profile ID and `studyId`. Sample-list metadata carries the stated `sampleCount` when the source sends it and has no field for member sample IDs. A file reference labels GitHub `size` as repository blob size, never data content size. The card carries the bundle revision and acquisition time, and each live section carries its own acquisition time, so the two times stay visible apart. `groups` and `readPermission` stay access metadata, never a reuse license.
- Proof: cases first. Type review checks each field's absence, multiplicity and collection scope against the j14206, j14214 and j14223 captures. Round-trip tests cover the study ID form, refusal of a malformed ID before I/O, multiple PMIDs, an absent patient count distinct from a stated zero, and a sample-list record that cannot hold member IDs. The generated schemas are checked in with snapshot and compatibility checks, and existing schemas stay unchanged. This ticket adds no filter or exact-ID get and makes no provider call; each filter and exact-ID get that later study tickets add has a known-positive capture through one bounded keyless pm job. No licensed content enters the repo, and replies whose terms bar storage replay from outside the repo. Then make landing-gate runs through pm job.
- Defers: the `counts` section, `--gene`, the gene aggregate record and `biomcp.study_counts/1` move to 0223, behind 0207's filtered-request witness. Executable help, Markdown parity and the shared request, step and envelope schema versions move to 0213, which registers study in the shared request.
