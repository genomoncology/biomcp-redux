# 0030 — Add the clingen section from the ClinGen bundles

Status: OPEN.

Milestone: 1

## Outcome

`biomcp sync clingen` stores the ClinGen gene-validity and dosage CSV files as local bundles, and `get gene <input> clingen` answers each card's validity rows, haploinsufficiency and triplosensitivity from the local bundles, automatically syncing first use within the leg budget and making no request while both bundles are fresh, proven by gene.md cases 14 and 17 under their ceilings.

- Unchecked: whether either host honors `Range` or `If-Modified-Since`; the files are generated per request. ClinGen's published request limit; declare a conservative local quota `clingen` of 1 request per second and 1 in flight in quotas.rs.
- PM decision: 2026-10-24. Add `RowFormat::Csv { banner_lines }` to the bundle parser: skip that many leading lines, read the next as the header, drop rows whose every cell is a run of `+`, and parse RFC 4180 quoting with commas inside quotes. Both bundles declare `banner_lines: 4` and `Freshness::Days(1)`. With no ETag and a moving `Last-Modified`, each sync downloads the whole file; both fit under `auto_sync_max_bytes`, so first use syncs automatically. `biomcp sync clingen` syncs both files, like `biomcp sync hgnc`. Rows key on the HGNC ID only, because HGNC owns identity.
- PM decision: 2026-10-24. `Section<ClinGenGene>` holds `validity` rows (disease label, MONDO ID, mode of inheritance, classification, classification date, expert panel, report URL) in file order, then `haploinsufficiency`, `triplosensitivity` and the dosage date. The rows sit inline whole, because the checked snapshot has at most 7; this is not a permanent source cap (architecture 3.10 rule 4). A gene in neither file is `Empty` with no record. The section is never `NotApplicable`. Classifications are shown as ClinGen states them.
