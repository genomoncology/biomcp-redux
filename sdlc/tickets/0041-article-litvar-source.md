# 0041 — Add LitVar2 as a variant source with an exact-match rule

Status: OPEN.

Milestone: 1

## Outcome

`search article --variant TEXT [--gene INPUT] --source litvar` returns every PMID LitVar2 lists for the one variant whose gene and protein change, or rsID, match the input exactly, returns the candidates and runs no search when none or several match, and refuses before any request a filter or sort that a named source cannot apply, through the CLI and MCP.

- PM decision: 2026-10-24. `Source::LitVar` (`litvar`) lands here and `source` widens to it. `litvar` needs `--variant`: an rsID alone, or a protein change with `--gene`. BioMCP sends autocomplete the resolved symbol and the change, or the rsID, and takes the one hit whose `gene` list holds the symbol and whose `name` equals `p.` plus the change without case, or whose `rsid` equals the input. No match or several matches answer status absent with no publications request and up to five candidates, each with its rsID, gene, name and PMID count, as disambiguate steps that rerun the search with `--variant` set to the candidate's rsID. The outcome's `term` is the chosen rsID. The whole list is one call, capped at 9,999 PMIDs with `page.truncated` and LitVar2's `count`, in LitVar2's order. `litvar` applies no words, `--disease`, `--drug`, `--author`, `--journal`, `--since`, `--until`, `--type` or `--sort date`; naming it with any of them is a usage error, code `usage.unsupported_filter`, that names the source and the option before any request; `--variant` missing is the same error naming `--variant`. A default search with `--gene` and `--variant` adds a `next` step with `--source pubmed,litvar`. `--help` for `--source` gains the `litvar` line from article.md.
