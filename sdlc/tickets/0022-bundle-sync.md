# 0022 — Sync local data bundles into indexed rows

Status: OPEN.

Milestone: 1

## Outcome

Fetch::sync downloads a declared TSV bundle under its lock and sync budget, resumes a kept part file, and stores every row with its exact keys and FTS5 words in one transaction, and Leg::rows answers exact, prefix and word finds with fresh, stale, syncing and offline outcomes, proven through the public crate API against a local stub server.

Depends on: 0020

- Starts from: architecture 4.2 (Fetch::sync, Leg::rows), 4.9, 4.11, 7.1–7.3 and 10.4; lib.rs FetchConfig/Fetch/Leg/LegReport/finish; cache.rs Cache::open/initialize (its orphan check already names the five bundle tables) and VERSION; request.rs status mapping and stale fallback; record.rs Recordings, Body::Text, MAX_FILE_BYTES and ReplayCache; deadline.rs; declaration.rs SourceSpec/Freshness; tests/support/mod.rs local stub.
- Changes: `crates/biomcp-fetch/src/lib.rs`, `crates/biomcp-fetch/src/bundle.rs`, `crates/biomcp-fetch/src/bundle/**`, `crates/biomcp-fetch/src/cache.rs`, `crates/biomcp-fetch/src/record.rs`, `crates/biomcp-fetch/src/request.rs`, `crates/biomcp-fetch/src/retry.rs`, `crates/biomcp-fetch/tests/bundle.rs`, `crates/biomcp-fetch/tests/support/mod.rs`.
- Checked boundaries, 2026-10-24: the HGNC host answered `Range: bytes=0-40000` on https://storage.googleapis.com/public-download-files/hgnc/tsv/tsv/hgnc_complete_set.txt with 206, `content-range: bytes 0-40000/16982321`, `accept-ranges: bytes`, `etag: "cfb3e2337755e56baa4fa648a96765b2"`, `last-modified: Fri, 16 Oct 2026 13:36:15 GMT`, `cache-control: no-store` and `text/plain;charset=utf-8`. The full file is 16,982,321 bytes of LF-terminated ASCII with a header row and 53 tab-separated columns on every one of its 45,278 lines. A cell that holds a list is wrapped in double quotes, such as `"BRAF1|BRAF-1"`, and no cell holds an inner quote. The file is larger than the default `max_body` of 8 MiB and the recording cap `MAX_FILE_BYTES` of 16 MiB. Cargo.lock pins libsqlite3-sys 0.38.2, whose build.rs compiles bundled SQLite 3.53.2 with `-DSQLITE_ENABLE_FTS5`.
- Reviewed HTTP boundaries, 2026-10-24: Range bytes=0-0 returned 206 with total 16,982,321; matching If-None-Match returned 304. Deliberately mismatched If-Range still returned 206, so it cannot safely resume this host alone. Mismatched If-Match returned 412. Resume with Range plus stored strong ETag in If-Match; restart after 412. Validate returned ETag and Content-Range offset/total before append; without a safe validator restart. Read-only review fetched zero/one byte apart from the small 412 body. Primary contracts: https://docs.cloud.google.com/storage/docs/xml-api/get-object-download and https://www.rfc-editor.org/rfc/rfc9110.html .
- PM decision: 2026-10-24. Add `Bundle<R: Row>`, `Row::keys`, `Keys`, `KeyKind`, `Find`, `RowFormat::Tsv` and `BundleInfo` as architecture 4.11 names them. Only `RowFormat::Tsv` lands, because HGNC is the only consumer. The header names the columns, quotes that wrap a whole cell are removed and an empty cell is absent. List splitting stays in the adapter's map, because HGNC's withdrawn file separates merge reports with ", " and their parts with "|".
- PM decision: 2026-10-24. `bundle_row.row` stores each row as a JSON object of its named non-empty cells, so a read needs no header and decodes `R` with the existing serde_json path. Exact keys are stored with ASCII case folded, because resolution matches symbols without case (architecture 6.2). A prefix find is an escaped range on the `bundle_key_find` index, never `LIKE`, so `%` and `_` in input stay literal. A word find quotes every input word as an FTS5 string with inner quotes doubled, so input never reaches FTS5 query syntax. Finds return every match in row order with no cap, because a bundle bounds its own rows.
- PM decision: 2026-10-24. Keep cache VERSION 1 and add the bundle tables with `CREATE TABLE IF NOT EXISTS`, because no release has shipped a version-1 file. FetchConfig gains `sync_budget` and `auto_sync_max_bytes` (32 MiB default) and a named `MAX_BUNDLE_BYTES` constant bounds downloads in place of `max_body`. A first-use bundle has no last known size, so an auto-sync reads the reply's Content-Length or counts bytes and stops above the limit, keeping the part file and answering `syncing`.
- Scope: Fetch::sync acquires the unique bundle_sync holder, revalidates stored ETag/Last-Modified, streams to its owned part under sync_budget, safely resumes with Range/If-Match or restarts on 200/412, and replaces rows, keys and words in one transaction after validation. Automatic sync uses the same bounded operation; ordinary row reads remain within the leg deadline. Live holder contention, expired sync budget or auto-size limit answer Syncing and keep the owned part. Cut/short/malformed downloads leave old rows untouched. Leg::rows syncs absent/stale data; provider failure may serve stale rows with retained failure. Offline never syncs. Local cache/recording errors stay RequestError local errors, never provider failures or stale successes.
- Keeps: Existing JSON, XML, POST, cache, retry, quota, record, replay and offline behavior and their tests stay. Reply cache entries and bundle rows never mix. No adapter, source declaration, CLI command, CSV or JSON row format, pool table or new dependency.
- Proof: New public contract tests in `crates/biomcp-fetch/tests/bundle.rs`, under the 10.4 allowance, serve a small TSV with quoted lists from the shared stub. They prove first sync and row decode, case-folded exact finds, a `9p21.` prefix that leaves out `19p21` and treats `%` and `_` literally, word finds whose input holds quotes, `*`, `AND` and `NEAR(` without an FTS5 error, and a fresh SQLite file whose `bundle_words` table is created by the FTS5 module. They also prove 304 revalidation that keeps rows and moves `fresh_until`, a new ETag that swaps rows in one transaction, a held lock answering `syncing` and a stale lock taken over, and a stalled body that keeps its part file and resumes. A stub that ignores `Range` causes a restart. The Content-Length limit answers `syncing`, a 500 on a stale bundle serves stale rows with the failure retained, and offline makes no request. Replay of a recorded slice needs no server, and a cut body or a bad row keeps the old rows. Then make landing-gate runs through pm job after current main.
- Defers: The HGNC bundle declarations, the live record run and the trimmed slices go to 0023. `biomcp sync`, the `sync` next step and binary configuration of the budget and size limit go to 0025, because the binary has no transport dependency or bundle list before then. Other row formats wait for their first bundle.

- Reviewed API: Bundle APIs return RequestError. BundleInfo contains name, bytes, rows and freshness, never local paths/provider diagnostics. RowFormat has only Tsv; Row/Bundle/Keys/KeyKind/Find otherwise follow architecture 4.11. HTTP uses the existing agent, validation, configured credentials, quota, retry classification and recording owner; extract a narrowly named shared wire helper if needed and correct Changes, with no second client/policy. Include declaration.rs/deadline.rs only if actually changed.
- Lock and file ownership: Each unique holder owns its part. Lease takeover fences the former holder from publication, resume metadata, release of a replacement lock, deletion or truncation of successor files. Publication/release compare holder identity. Part metadata binds bytes to URL/validator. Restart/cleanup touch only caller-owned files. SQL locks surround SQL only.
- Parsing and finds: Require unique nonempty headers, correct column counts and valid whole-cell quote wrapping; preserve inner contents. Bad rows leave old rows/keys/FTS intact. Word terms are quoted FTS strings joined by AND; blank or punctuation-only input has no matches. Prefixes remain literal indexed ranges. FTS primary evidence: https://sqlite.org/fts5.html#fts5_strings .
- Record and replay: Record bypasses bundle-cache reads, revalidation and partials and records one complete successful reconstructed 200 text body with canonical GET identity. Replay imports the full/trimmed recording once per bundle per Fetch, replacing prior case rows even when warm; later finds in that Fetch reuse imported rows without another cursor consumption. No ordinary user-cache import, network or part file. Offline reads checked case rows without consuming recordings. Preserve existing GET/POST files.
- Recording bounds: Keep ordinary reply limits unchanged. MAX_BUNDLE_BYTES bounds raw bytes; a separate named bounded publication/read allowance also fits the JSON escaping and metadata for a complete bounded TSV body. One existing recording reader/writer owns both classes; no sidecar or alternate capture client.
- Additional proof: Independent processes contend on the same cache; after takeover a paused old holder cannot publish, release the new lock or damage its part. Mismatched If-Range/ETag, wrong range offset/total and 412 never combine representations. Routine fixtures exercise escaped recording encoding; the release suite includes an actual body larger than the prior recording cap. Replay replaces prior case rows. No repeated live If-Range investigation is needed.

- Settled signatures: Fetch::sync(&Bundle<R>) -> Result<BundleInfo, RequestError>; Leg::rows(&Bundle<R>, Find) -> Result<Vec<R>, RequestError>. Successful BundleInfo carries the named bundle/count/freshness data. Stale state remains in LegReport; absent/offline and syncing use existing SourceError reasons. Add no Rows wrapper or duplicated BundleState enum.
