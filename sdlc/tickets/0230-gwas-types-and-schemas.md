# 0230 — Add the GWAS types and generated schemas

Status: OPEN.

Milestone: 4

Depends on: 0205

## Outcome

`biodata` holds the neutral, no-I/O GWAS values that `planning/slices/gwas.md` names: a checked GCST study accession, a positive association ID qualified as a GWAS Catalog association, a source ontology trait ID that keeps every source namespace such as MONDO and EFO, and an exact scientific p value that keeps the source mantissa and exponent. `biomcp-types` holds the consumer side: `GwasSearch` with optional `--variant`, `--trait`, `--trait-id`, `--gene`, `--study` and `--pubmed` selectors, `--include-child-traits` and `--extended-geneset` off by default, `--p-value`, the echoed order, native p value ascending by default, and `--limit` and `--offset` with a default page of three; `GwasGet` as an explicit study-or-association sum, with the association section `loci` and the study sections `associations` and `ancestries`, and `--section-limit` and `--section-offset`; the association header page, the association card, the locus section, the study card and the ancestry section. The generated, checked-in schemas are `biomcp.gwas_page/1`, `biomcp.gwas_association/1`, `biomcp.gwas_loci/1`, `biomcp.gwas_study/1` and `biomcp.gwas_ancestries/1`. The existing shared association record gains the exact p-value parts, and the variant schemas that embed it take their next version with a compatibility check, so `get variant ID gwas` keeps its fields and gains the exact value.

- Why: the slice method lands types and schemas before adapters, and the accepted design with the GWAS rulings fixes the identities, the command tree and the page shapes.
- Starts from: gwas.md's identity and joins, fields proved by capture, proposed types and schemas and command tree, with the GWAS rulings in `decisions/2026-10-26-protein-pathway-study-rulings.md`, which win over the design text; 0205's witnesses and the 0193 archives; `GwasAssociation`, `GwasTrait` and `GwasEffectAllele` in `crates/biomcp-types/src/response/variant_population.rs`; the raw records in `crates/biomcp-adapters/src/gwas/raw.rs`; `rust-standards.md`; the existing variant identity and text types.
- Rules: each fact has one definition, and the search page, the study `associations` section and the variant section share the one association record. An association keeps its ID, study accession, reported-trait array, mapped-trait ID and label array, every rsID and effect-allele pair, exact p value, odds ratio, beta text, interval, frequency text including NR, PMID, author and source mapping context; missing values stay optional, and an unknown frequency is never zero. Odds ratio and beta are separate optional fields, and neither overrides the other. A p value that underflows a double keeps its mantissa and exponent and never becomes zero. A trait ID type never restricts to an EFO prefix. A study card keeps discovery and replication sample text and ancestry summaries apart, and an ancestry row never sums independent samples into unique people. A summary-statistics flag or link is not proof of a download or license. Study sections reject an association input, and `loci` rejects a study input, before I/O. Empty search input is a usage error, never a whole-catalog scan. `--p-value` with any sort other than the default p-value-ascending order is a usage error. The 0.9 positional query is the `--gene` alias, and `-g` and `-l` stay aliases; none infers a trait. A selector or field that 0205 left unproven stays out of the schema. No local risk label, inferred disease name or gene heuristic.
- Proof: cases first. Type review checks each field's absence, multiplicity and collection scope against the 0193 captures and 0205's witnesses. Round-trip tests cover each ID form, including refusal of a malformed GCST accession, a zero association ID and a trait ID with no namespace, and exact p-value parsing for 2e-76 and for an exponent below the double range. Request tests show each section and input pairing failure before I/O. The generated schemas are checked in with snapshot and compatibility checks; the variant schema version change keeps every existing field, and the existing variant GWAS cases replay unchanged except for the added exact value. This ticket adds no filter or exact-ID get and makes no provider call; each filter and exact-ID get that later GWAS tickets add has a known-positive capture through one bounded keyless pm job. Source replies stay outside the repo. Then make landing-gate runs through pm job.
- Defers: executable help, Markdown parity and the shared request, step and envelope schema versions move to 0234, which registers gwas in the shared request.
