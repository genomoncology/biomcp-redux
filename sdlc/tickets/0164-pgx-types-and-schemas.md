# 0164 — Add the pharmacogenomics types and generated schemas

Status: OPEN.

Milestone: 4

Depends on: 0163

## Outcome

`biodata` holds the neutral, no-I/O pharmacogenomics records that `planning/slices/pharmacogenomics.md` names: `PgxPair`, `PgxGeneIdentity`, `PgxGuidelineReference`, `PgxRecommendation`, `PgxDiplotypeResult` and `PgxAnnotationHeader`, and `PgxAnnotationDetail` only if 0163 proved the single base get. A ClinPGx accession is its own checked type, distinct from the shared `PaId`. `biomcp-types` holds the consumer side: the `search pgx` request with a required `--gene`, a required `--source cpic`, `--cpic-level`, `--limit` and `--offset`; the `get pgx` request with `--gene`, a required `--source`, the CPIC sections `recommendations`, `guidelines` and `diplotype` with `--diplotype`, the ClinPGx section `annotations` with `--kind clinical|guideline|label` defaulting to `clinical`, and `--section-limit` and `--section-offset`; a native drug selector on `recommendations` only if 0163 proved the `drugid` filter; the pair header page, the gene identity card and each section page. The generated, checked-in schemas are `biomcp.pgx_page/1`, `biomcp.pgx_card/1`, `biomcp.pgx_guidelines/1`, `biomcp.pgx_recommendations/1`, `biomcp.pgx_diplotype/1` and `biomcp.pgx_annotations/1`.

- Why: the slice method lands types and schema before adapters, and the accepted design with the 0153 PM rulings and recheck amendments fixes the records, the command tree and the page shapes.
- Starts from: pharmacogenomics.md's domain and identity boundaries, JSON body shapes and command tree, with the 0153 amendments, which win over the design text; the j12644 field and optionality inventories and 0163's witnesses on the evidence store; `rust-standards.md`; the existing gene and variant identifier types.
- Rules: star alleles and diplotypes stay native records with no `Statement`, no `statement_unmapped` flag and no new shared `Subject` kind, and no ClinPGx level maps to a shared proposition. CPIC pair level, ClinPGx level and recommendation classification stay separate fields, and pair levels stay open text so `B/C` survives. A gene record version is not a dataset release. A recommendation keeps its complete multi-gene lookup key, native drug name, population and comments, and carries no drug ID unless 0163 proved one. A diplotype result keeps the source expression and literal `n/a`, with no sorted alleles, phase or computed score. A collection page says whether its total is the source's or observed. `--source cpic` is required on search, the card, `recommendations`, `guidelines` and `diplotype`; `annotations` requires `--source clinpgx`; any other source and section pairing fails before I/O, including `get pgx --gene X --source clinpgx` with no section. There is no positional search, no `--drug` text, no `--population`, no `--lookup-key`, no `--pgx-testing`, no pair card, no frequency type or schema and no `all` section. `biomcp.pgx_annotation/1` is deferred with its command unless 0163 proved the base get, in which case this ticket adds it.
- Proof: cases first. Type review checks each field's absence, multiplicity and collection scope against the j12644 captures and 0163's witnesses. Round-trip tests cover each ID form and each closed set, including refusal of a ClinPGx accession as a `PaId` and of each bad source and section pairing before I/O; a test shows the diplotype and recommendation types cannot become a `Statement`. The generated schemas are checked in with snapshot and compatibility checks, and existing schemas stay unchanged. This ticket adds no filter or exact-ID get and makes no provider call; each filter and exact-ID get that later pharmacogenomics tickets add has a known-positive capture through one bounded keyless pm job. No licensed content enters the repo, and replies whose terms bar storage replay from outside the repo. Then make landing-gate runs through pm job.
- Defers: executable help, Markdown parity and the shared request, step and envelope schema versions move to 0166, which registers pgx in the shared request.
