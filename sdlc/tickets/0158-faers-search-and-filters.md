# 0158 — Search FAERS reports with positional text and four typed filters

Status: OPEN.

Milestone: 3

Depends on: 0156
Depends on: 0157

## Outcome

`search adverse-event TEXT` with no `--source`, or with `--source faers`, sends the literal expression `(patient.drug.openfda.generic_name:"TEXT" OR patient.drug.openfda.brand_name:"TEXT" OR patient.drug.medicinalproduct:"TEXT")` to openFDA's drug event endpoint sorted by `receivedate:desc` and returns a five-row page of report headers in source order, with the native total in reports, the publisher's `last_updated` date apart from the retrieval date, and the exact query text built. `--reaction TERM` adds `AND patient.reaction.reactionmeddrapt:"TERM"`, which openFDA treats as a phrase match on an analyzed field, and help and the query echo say phrase match. `--serious death` adds `AND seriousnessdeath:1` and `--serious hospitalization` adds `AND seriousnesshospitalization:1`. `--received-from` and `--received-to` add `AND receivedate:[YYYYMMDD TO YYYYMMDD]` for first FDA receipt, with `*` for a missing bound. `--limit` and `--offset` page natively, and the page step keeps every selector. Each header row offers one exact get as its disambiguate step, then the page step, then at most three other steps, under architecture 6.10.

- Why: the first question names a drug and a reaction, and the design makes FAERS the default source with positional input and four typed filters, each tied to a captured positive row.
- Starts from: adverse-event.md's command tree, query builder paragraph and command and option cases, with 0152 recheck amendment 1; the j12641 capture rows F01 to F23; the shared transport and adapter shape in `architecture.md`; 0156's types and 0157's registry.
- Rules: the text is a literal search, never an identity join, a name expansion or a chosen drug. No local synonym, spelling retry, trial fallback or source probing. A `.exact` reaction selector waits for its own captured positive. A combined filter builds its conjunction, and no case claims a native positive for a combination the capture lacks, so A04's fatal subset and A15's combined reaction and date question stay unanswered. The default page does not pick one drug as a report's drug. Report totals are never presented as incidence, risk or causation.
- Proof: outside-in cases first, watched to fail. Before adapter code, one bounded keyless pm job sends each case's exact request once, with zero retries, and records the replies; each case asserts the captured facts with that date, and the j12641 figures are the expected witnesses. F01 asserts the default page, its first report and its total (105,020 on 2026-10-25, first report 26940567 version 1) and equality between no `--source` and `--source faers`; F20 asserts the second page at offset 5 with the same total; F02 and F03 assert the `--reaction` phrase match for pembrolizumab with MYOCARDITIS (2,147) and PNEUMONITIS (2,608); F23 asserts osimertinib with PNEUMONITIS (134); F13 and F14 assert `--serious death` (18,819) and `--serious hospitalization` (44,253); F15 asserts both receipt bounds for 2024 (16,093). Synthetic builder cases cover each one-sided date bound, literal escaping, empty text and a combined filter, each labeled synthetic. The job measures the default and filtered pages in CLI and MCP output, records cold and warm timings and the measured sizes in adverse-event.md's budget table, and each case gets a ceiling at measured size plus 15 percent. No licensed content enters the repo, and replies whose terms bar storage replay from outside the repo; replies that carry MedDRA reaction terms follow 0157's terms reading. Then make landing-gate runs through pm job.
