# 0011 — Cache checked source replies in SQLite

Status: OPEN.

Milestone: 1

## Outcome

The shared transport reuses fresh checked replies, serves stale replies only under the documented fallback rules, and never stores failed or unchecked provider bodies.

Depends on: 0008

- Starts from: `sdlc/plan.md` stage 4; architecture sections 4.4, 4.8, 7.1–7.3 and 7.5; the existing request identity, quota/retry path, public transport tests and approved dependency metadata.
- Changes: `Cargo.toml`, `Cargo.lock`, `deny.toml`, `crates/biomcp-fetch/Cargo.toml`, `crates/biomcp-fetch/src/lib.rs`, `crates/biomcp-fetch/src/declaration.rs`, `crates/biomcp-fetch/src/request.rs`, `crates/biomcp-fetch/src/error.rs`, `crates/biomcp-fetch/src/cache.rs`, `crates/biomcp-fetch/src/cache_request.rs`, `crates/biomcp-fetch/tests/transport.rs`, `crates/biomcp-fetch/tests/retries.rs`, `crates/biomcp-fetch/tests/quotas.rs`, `crates/biomcp-fetch/src/retry.rs`, `crates/biomcp-fetch/tests/cache.rs`, `crates/biomcp-fetch/tests/support/**`, `crates/biomcp/tests/ratchets/source.rs`.
- Scope: Add an optional explicit cache path (absence disables storage), exported fetch schema version and owner/version meta row. Initialize/check the owner row transactionally. Refuse a mismatched version before changing journal mode or transport schema, and do not adopt transport tables lacking a valid owner row. Preserve other owners/tables. Open SQLite in WAL mode with busy handling and a reasoned transport Mutex limited to SQL operations, released before HTTP, quota waits, decoding and checks. Bound request-time busy waits by remaining deadline. Add endpoint Freshness and one reply table keyed by the existing credential-free GET identity. Derive stored URL and key from one request representation; later methods extend it when implemented. Revalidate decode and Reply::check on every read. Write only validated 2xx bodies and a 404 absence entry with empty body and the documented ten-minute freshness, never decoded or checked; store no other status or rejected body. A fresh hit makes no request or quota wait. Never freshness bypasses storage. Only Mode::Live {fresh} exists in this step. Fresh bypasses reads and stale fallback but writes checked results. When quota/send/body/decode/check fails, a previously checked stale 2xx reply may return with the original failure retained in Leg::finish()->LegReport. Stale state persists across subsequent successful calls. No-key and foreign-endpoint refusals never use cache. A current 404 replaces a positive entry and returns absence; expired negatives never provide stale fallback. Refuse owner-version mismatch without destructive migration.
- PM decision: 2026-10-24. Optional path disables storage when absent, endpoint Freshness defaults to Never, fresh bypasses reads/fallback, and 404 entries replace positives and never supply stale absence after expiry. Stale positive replies retain the typed source failure in the leg report.
- PM decision: 2026-10-24. Request methods return typed RequestError::Source(SourceError) or RequestError::Cache(CacheError). A local database error never masquerades as provider failure or triggers stale fallback. Keep reports' provider failures typed as SourceError.
- PM decision: 2026-10-24. A cached body failing the current Reply check or body limit is evicted and treated as a miss. Take the normal source path and never use that body as stale fallback. Real SQLite open/read/write errors remain local Cache failures.
- Reviewed implementation detail: Preserve Leg Send+Sync with a short report-state Mutex separate from the SQL mutex.
- Keeps: One request/retry path, no separate cache HTTP client. Required-key refusal precedes all cache access. No credential in keys, URLs, database bodies authored by the transport, diagnostics or Debug. Caller-owned SQLite files and old versions are never dropped or silently migrated. SQL stays in the fetch cache module. No bundle or pool tables, cache cleanup command, XML, recording or replay placeholders.
- Proof: Public local-server cases prove fresh hit with zero second requests, fresh bypass, Never bypass, checked-body rejection with no stored hit, short-lived negative caching, stale fallback with its reason, and revalidation failure by reading a stored reply through a stricter public Reply type, and reads respecting current body limits. Assert ordinary params yield distinct keys while changing configured credentials preserves identity, including missing-key refusal after another client populated the cache. Exercise owner-version refusal and two actual child processes with event coordination: concurrent first opens and overlapping distinct-key writes both succeed, then a new process reads both replies without HTTP. Two Fetch values or sequential subprocesses are insufficient. Seed expiry through the documented SQLite file contract rather than real minute-long sleeps or a product test hook. Run make landing-gate through pm job after merging current main.
- Defers: Offline and recording/replay modes with virtual quota time follow as the next transport step. The binary builds versioned cache filenames when it owns config. Bundle and pool tables wait for their slices. The transport roadmap item remains unticked until its full stage is complete.
