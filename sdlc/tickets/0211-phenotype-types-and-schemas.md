# 0211 — Add the phenotype types and generated schemas

Status: OPEN.

Milestone: 4

Depends on: 0208

## Outcome

`biodata` holds the neutral, no-I/O phenotype records that `planning/slices/phenotype.md` names: a checked HP identifier type for the published HP grammar, `PhenotypeHeader`, `PhenotypeCard`, `PhenotypeSynonym`, a cross-reference row and a hierarchy link that holds the related term's exact ID, label and native relation. Association rows reuse the disease slice's `DiseaseAssociation` record. That record has no source taxon field at the starting revision, so it gains an optional native subject taxon, kept only as sent. `biomcp-types` holds the consumer side: the `search phenotype TEXT` request with `--source monarch` as its default and only source, `--limit` and `--offset`; the `get phenotype HP:ID` request with `--source hpo|monarch`, the sections `synonyms` and `xrefs` for `hpo` and `monarch`, and `hierarchy`, `diseases` and `genes` for `monarch`, with `--section-limit` and `--section-offset`; the header page, the term card and each section page. The generated, checked-in schemas are `biomcp.phenotype-search/1`, `biomcp.phenotype-card/1`, `biomcp.phenotype-synonyms/1`, `biomcp.phenotype-xrefs/1`, `biomcp.phenotype-hierarchy/1`, `biomcp.phenotype-diseases/1` and `biomcp.phenotype-genes/1`.

- Why: the slice method lands types and schema before adapters, and the accepted design with the PM's phenotype rulings fixes the records, the command tree and the page shapes.
- Starts from: phenotype.md's proposed types, schema and commands, source fields and progressive disclosure sections, with the Phenotype rulings in `2026-10-26-protein-pathway-study-rulings.md`, which win over the design text; the j14204, j14210 and j14227 field inventories and 0208's witnesses on the evidence store; `crates/biodata/src/disease.rs` and the disease association schemas; `rust-standards.md`.
- Rules: a header holds the HP ID, native label and the optional native match score, matched field and match type, and a score keeps the publisher's meaning. The card is one schema with a closed source tag, so an HPO card and a Monarch card never merge. The HPO card holds the requested ID, returned ID, label, complete definition, comment, publication references and descendant count as source metadata. The Monarch card holds the requested ID, returned ID, label, complete description, association counts with their scopes and the native deprecation fact only if 0208 proved it. HPO and Monarch descendant counts stay separate fields. A synonym keeps its publisher relationship class when Monarch sends one, and an HPO synonym stays unclassified. An empty definition, comment or list stays distinct from an absent field, and no nonempty text rule drops a native empty value. The Monarch `xrefs` pairing exists only if 0208 proved a positive Monarch xref. Defaults are five search headers, five rows for `synonyms`, `xrefs` and `hierarchy`, and one row for `diseases` and `genes`; explicit valid limits keep their checked values. A MONDO, gene or malformed identifier on `get phenotype` fails before I/O, and every source and section pairing outside the list above fails before I/O, including `search phenotype --source hpo`. PM ruling 2026-10-26: `get phenotype HP:ID` defaults to `hpo` for the card, `synonyms` and `xrefs`; `--source monarch` selects the Monarch card and its versions of those sections. `hierarchy`, `diseases` and `genes` exist only in Monarch, so they use Monarch without a flag, and naming `--source hpo` with them fails before I/O. There is no similarity type, translation field, patient, score, symptom parser, diagnosis type or `Statement`.
- Proof: cases first. Type review checks each field's absence, multiplicity and collection scope against the retained captures and 0208's witnesses. Round-trip tests cover the HP identifier grammar, each closed set and each bad source and section pairing before I/O; a test shows a phenotype association row cannot become a `Statement`. The generated schemas are checked in with snapshot and compatibility checks. The disease association, genes and phenotypes schemas take the version step the compatibility check requires for the optional subject taxon, and every other existing schema stays unchanged. This ticket adds no filter or exact-ID get and makes no provider call; each filter and exact-ID get that later phenotype tickets add has a known-positive capture through one bounded keyless pm job. No licensed content enters the repo, and replies whose terms bar storage replay from outside the repo. Then make landing-gate runs through pm job.
- Defers: executable help, Markdown parity and the shared request, step and envelope schema versions move to 0217, which registers phenotype in the shared request.
