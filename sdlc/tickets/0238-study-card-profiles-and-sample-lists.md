# 0238 — Get the study card with its profiles and sample-lists sections

Status: OPEN.

Milestone: 4

Depends on: 0210
Depends on: 0213

## Outcome

`get study brca_tcga_pan_can_atlas_2018` returns the exact study card from the stored catalog bundle: study ID, native name, description, native cancer-type code, `allSampleCount`, `sequencedSampleCount`, `cnaSampleCount`, `structuralVariantCount`, `treatmentCount`, `referenceGenome`, citation, every PMID, the native import date, the source study URL, the bundle revision and the source-wide restricted terms. `get study ID profiles` reads the captured `molecular-profiles?projection=DETAILED` route for the study and returns five native profile summaries per page with exact profile ID, `studyId`, native alteration type, data type, name and description, with no repeated embedded study record. `get study ID sample-lists` reads the captured `sample-lists?projection=DETAILED` route, because the SUMMARY projection carries no `sampleCount`, and returns five list summaries per page with exact list ID, `studyId`, category, name, description and the stated `sampleCount` when sent. Both sections page with `--section-limit` and `--section-offset`. `all` returns each named section's bounded first page.

- Why: the second study question asks what one call can say about a cohort, and the 2026-10-26 study rulings accept `get study` with `profiles` and `sample-lists`.
- Starts from: study.md's command tree, types table, case map, captured source findings, clinical review boundary and measured disclosure budget, with the 2026-10-26 study rulings, which win over the design text; the j14206 study, profile and sample-list captures; the existing cohort checks in `crates/biomcp-adapters/src/cbioportal/mod.rs`; 0213's dispatch registration and bundle; 0210's types.
- Rules: the card reads only the stored bundle and never triggers a sync. A get uses only an exact, case-sensitive study ID, and an absent ID returns not found with no alias, fallback or guessed cohort. A malformed ID fails before I/O. Each profile and sample list must carry the requested `studyId`, or the record is dropped with a problem and never enters the cache. Profile IDs are captured and never built by appending a suffix to a study ID. A profile label never proves every locus was assayed, and a missing profile type is never a negative finding. A sample-list `sampleCount` is membership only and never an altered-sample or gene-assayed count. The adapter discards `sampleIds` at parse, never counts them, and no participant sample ID enters product output, fixtures or the repo. An absent `sampleCount` stays absent and never reads as zero. The sample-lists admission bound covers the measured 1,327,332-byte MSK reply plus 15 percent, and a larger reply returns an incomplete problem, never a cut page. Source-wide `restricted` use stays, and a disabled source or group skips each section before cache or network. Next steps follow architecture 6.10: the card gives `profiles` and `sample-lists` section steps, and a section page gives its page step.
- Proof: outside-in cases first, watched to fail. Before adapter code, one bounded keyless pm job captures each case's exact request once, with zero retries, and records the replies. Card cases assert S01 to S20's study IDs, native cancer-type codes and `allSampleCount` values; S11 to S15 assert `sequencedSampleCount` beside `allSampleCount`; S16 to S19 assert `cnaSampleCount` beside `allSampleCount`; S20 asserts that the description's prose count is not a patient field; an absent patient count stays absent; an absent study ID asserts not found; a malformed ID asserts a usage error with zero requests. Profile cases assert BRCA's 17 profiles across a complete page walk with no gap or duplicate, LUAD's 14 and MSK's three profile IDs with native types and no expression profile (S25). Sample-list cases assert BRCA's 13 and MSK's 60 lists with stated counts across a complete walk, and a case asserts that no output holds a `sampleIds` field or any member ID from the raw reply. A synthetic wrong `studyId` on a profile and on a sample list asserts the drop, the problem and no cache admission. Recorded 429, 500, timeout and broken-body cases for each section assert a failed outcome with source and terms, never an empty page. The job measures each command in CLI and MCP output, starting from the design's projections of 707 bytes for the card, 1,926 for a profile page and 1,424 for a sample-list page, and each case gets a ceiling at measured size plus 15 percent, recorded in study.md. Real replies fall under the restricted cBioPortal terms and hold public sample IDs, so they replay from outside the repo through `--cases DIR`, and synthetic replies prove failure mechanics. No licensed content enters the repo. Then make landing-gate runs through pm job.
