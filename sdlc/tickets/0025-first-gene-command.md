# 0025 — Answer get gene and search gene in the response envelope

Status: OPEN.

Milestone: 1

## Outcome

`biomcp get gene <input>...` and `biomcp search gene [TEXT] [--band BAND]` print the versioned JSON envelope with status, query echo, typed next steps and gene answers or header pages through the CLI and the one MCP tool, and the gene.md section 8 cases that need no section pass in replay under their byte ceilings.

- PM decision: 2026-10-24. The envelope follows 3.8 without `explain`. It carries only the Status, ItemStatus, SourceState, StepKind and ErrorCode values this ticket emits: source states ok, stale, syncing and failed; step kinds page, fresh, disambiguate and sync. `GeneItem { input, status, answer: GeneResolution }` holds each input, because slice section 5 controls the core shape (0021). Sections and `more` arrive later as optional item fields, which keeps `biomcp.gene_cards/1` compatible. The envelope's `sources` names hgnc and mygene, so no per-card sources list is added. `Section<T>` lands in biodata with its five states and round trips for each state. Its schema and first output arrive with the first section ticket, because no section source is in scope.
- PM decision: 2026-10-24. `GeneGet` takes 1 to 20 inputs. `GeneSearch` takes `query`, `band`, `limit` (1 to 50, default 10) and `offset`, and needs a query or a band. Text search ranks exact symbol, previous symbol, alias, then name words, with protein_coding first inside each kind and row order last. A record keeps its best match. Band search returns protein_coding first, then row order, with `match.kind` band. Name-word headers carry no match. The search `next` list holds `page` while results remain, then a disambiguate-kind `get gene <first HGNC ID>`. The get `next` list holds fresh, then sync, then one disambiguate step per ambiguous candidate, at most five steps and no repeats.
- PM decision: 2026-10-24. Replay never blocks in wall time, because it advances a virtual clock, so a delayed replay call cannot be in flight. The MCP scheduling proof deferred by 0015 and 0020 holds a real live call instead: the case config's `proxy` points at a runner-owned local listener that accepts CONNECT and sends nothing until the ping reply arrives. This adds the config file with `proxy` as its only key and unknown keys refused (9.1). It needs no fake slow command or product hook.
