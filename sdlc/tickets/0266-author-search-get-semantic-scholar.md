# 0266 — Search Semantic Scholar authors and get the Semantic Scholar author card

Status: COMPLETE.

Milestone: 4

Depends on: 0265

## Outcome

`search author "Louis Williams"` sends one Semantic Scholar author search with the text unchanged and native paging, and returns five headers in source order, each with the qualified ID, the source name, source affiliations and native paper and citation counts when supplied, and the next offset only when the source shows more. `get author semantic-scholar:ID` returns one `AuthorCard` per input in input order from one exact card request each, with the source name, counts with their scope, the provider link and at most five steps. `semanticscholar:ID` and `--source semanticscholar` keep working as aliases. Author registers in the shared request and command dispatch.

- Why: Questions A01, A03, A05, A07, A09, A11, A13, A16, A21 and A23 ask which provider records a source attaches to a paper or a name, and the design answers them with native candidates and an exact provider card.
- Starts from: author.md's command shape, delight questions and case list, with the author rulings and the new-sources decision; 0264's witnesses; 0265's types; the existing Semantic Scholar adapter, its `SemanticScholarApiKey` credential and its `noncommercial` terms; the shared transport, cache, pools and next steps in `architecture.md` 4 and 6.10.
- Rules: one unchanged query per search, with no name normalization, reranking or disambiguation guess. A name never becomes an ID, and no candidate gains an ORCID iD from a matching name. A returned author ID that differs from the request is dropped with a problem and never enters the cache. A well-formed ID with no record is absent, and a failed request is failed. The key comes from the config file, then `S2_API_KEY`, and is read only when Semantic Scholar is called; without it the request omits the key header and runs at the public rate. A 429 is a failed outcome with a `key` step where no key is set. Next steps follow `architecture.md` 6.10: a search page gives one `disambiguate` get per shown candidate, then the page step; the card gives the papers pivot. A topic-wide author rank is stated unavailable.
- Proof: outside-in cases first, watched to fail. Cases reuse 0264's captures where the request matches exactly, and one bounded pm job captures once, with zero retries and keys inherited by name only, any exact request a case needs that those archives lack. A21 asserts separate native candidates for `Louis Williams` and the next page with no overlap; A23 asserts the unavailable rank statement; A01, A05, A09 and A13 assert the exact byline records for their PMIDs through `get author`; A03 and A11 assert counts with scope and missing fields as unavailable; A07 and A16 assert no automatic link between similar names; the absent ID asserts absent distinct from failed; both alias spellings return the canonical card. A synthetic wrong returned author ID asserts the drop and no cache admission. Recorded 429, 500, timeout and broken JSON replies assert a failed outcome with source and terms, never an empty page. Paging usage cases cover a zero and an over-25 limit and a negative offset. The job measures each command in CLI and MCP output, and each case gets a ceiling at measured size plus 15 percent, recorded in author.md; a measurement over the design's stated bounds returns to the PM. No licensed content enters the repo. Then make landing-gate runs through pm job.
