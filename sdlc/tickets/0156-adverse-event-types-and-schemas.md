# 0156 — Add the adverse event types and generated schemas

Status: OPEN.

Milestone: 3

Depends on: 0152

## Outcome

`biodata` holds the neutral, no-I/O FAERS and MAUDE report records that `planning/slices/adverse-event.md` names. A FAERS record keeps the opaque `safetyreportid` and its separate `safetyreportversion`, the first FDA receipt `receivedate` and the latest-information `receiptdate` in their own roles, independent overlapping seriousness flags, patient age, age unit, sex and weight as source strings, reporter qualification and country, an ordered drug array and an ordered reaction array. Each drug object keeps `medicinalproduct`, its role code, indication, administration fields and the seven harmonized identifier arrays `unii`, `rxcui`, `product_ndc`, `package_ndc`, `spl_id`, `spl_set_id` and `application_number` in published form. Each reaction keeps its term as the shared `Concept` with a label and no CURIE, its MedDRA version in a separate field and its native outcome code. A MAUDE record keeps the opaque `mdr_report_key`, a separate `report_number`, the native event type, the distinct event, received, report and to-FDA dates, the native device and patient count strings, an ordered device array and an ordered narrative array. `biomcp-types` holds the consumer side: the `search adverse-event` request with positional text, `--source faers|maude` defaulting to `faers`, `--reaction`, `--serious death|hospitalization`, `--received-from`, `--received-to`, `--limit` and `--offset`; the `get adverse-event` request with an ID, `--source` defaulting to `faers`, the FAERS sections `drugs`, `reactions`, `unii`, `rxcui`, `product-ndc`, `package-ndc`, `spl-id`, `spl-set-id` and `application-number` with `--drug-index`, the MAUDE sections `devices` and `narrative`, and `--section-limit` and `--section-offset`; the report header, the FAERS card, the MAUDE card and each section page. The generated, checked-in schemas are `biomcp.adverse_event_page/1`, `biomcp.adverse_event_faers_card/1`, `biomcp.adverse_event_maude_card/1`, `biomcp.adverse_event_drugs/1`, `biomcp.adverse_event_reactions/1`, `biomcp.adverse_event_identifiers/1`, `biomcp.adverse_event_devices/1` and `biomcp.adverse_event_narrative/1`.

- Why: the slice method lands types and schema before adapters, and the accepted design with the 0152 PM review and recheck amendments fixes the records, the header, both cards and each section page.
- Starts from: adverse-event.md's identity and native semantics, the types, field lists and JSON shapes, and the command tree, with the 0152 amendments, which win over the design text; the j12641 native field inventory on the evidence store, which holds each kept source's exact-request captures; `rust-standards.md`; the shared `Concept` in `biodata`; the framing types in `biomcp-types`.
- Rules: the header carries only the published ID, source, optional version, optional native seriousness code, optional MAUDE event type and optional receipt date, with no flattened drug or reaction list and no chosen drug title. IDs such as `26940567` and `50952244` keep their published form with the source in a separate field, and no `FAERS:` or `MAUDE:` wrapper exists. `source_url` and `report_url` are card fields, never next steps. A page total counts reports and says so. Report totals do not reuse `CohortObservation`, because its shared contract requires a `VariantRef` subject and sample, patient or tumor units, and these totals count reports with no variant subject. Seriousness flags are not a CTCAE grade, and report hospitalization never maps to a reaction outcome code. A present empty source string stays distinct from an absent field. The seven identifier pages share one string-record shape under their closed section name. A narrative row too large for its page returns a too-large problem and is never cut. There is no `--version`, no count option, no reporter section, no `all` section and no vaccine type. Invalid or reversed dates, an unknown `--serious` value, a FAERS filter or section with `--source maude`, a MAUDE section with FAERS, and `--drug-index` outside the identifier sections fail before I/O.
- Proof: cases first. Type review checks each field's absence, multiplicity and collection scope against the j12641 captures, including 19-row drug arrays, 22-row reaction arrays, empty and five-row narrative arrays and the missing qualification in I01. Round-trip tests cover each ID form and each closed set, including refusal of a prefixed ID and of the before-I/O failures above; a test shows the header and cards carry no drug list, reaction list or count bucket; a test shows a reaction term serializes as a `Concept` with no CURIE. The generated schemas are checked in with snapshot and compatibility checks, and existing schemas stay unchanged. This ticket adds no filter or exact-ID get and makes no provider call; each filter and exact-ID get that later adverse event tickets add has a known-positive capture through one bounded keyless pm job. No licensed content enters the repo, and replies whose terms bar storage replay from outside the repo. Then make landing-gate runs through pm job.
- Defers: executable help, Markdown parity and the shared request, step and envelope schema versions move to 0158, which registers adverse-event in the shared request, as 0140 did for disease.
