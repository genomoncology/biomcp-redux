## Outcome

One bounded keyless pm job captures the admission witnesses that `planning/slices/protein.md` names as missing before the protein types are accepted, and the design records each one as proven, empty or failed. The witnesses are: a reviewed human UniProt text search with a literal query drawn from a harvested question that returns at least six records, at size five, and its second page through the exact continuation the first reply returns; one human UniProt search without the reviewed restriction that returns at least one unreviewed human record; an InterPro accession-scoped entry request at page size five for the accession with the largest native count in j14202, and its second page through the exact next pointer the first reply returns; one InterPro request that selects P04637's entries by the domain type, in the form InterPro documents; a human Complex Portal accession search for P15056 at five results per page, and its second page through the paging parameter Complex Portal documents; one exact UniProt entry request for the isoform accession P38398-2; and one exact UniProt entry request and one InterPro entry request for a well-formed accession that has no record. Raw replies, headers, the ledger and the recipe go to the evidence store, and no product code changes.

- Why: the slice method requires each kept source's exact-request captures before its shared types are accepted, and the design leaves these witnesses open. The investigation captured only one- and two-hit searches, no unreviewed positive, no second native page from any source, no isoform entry get and no absent record.
- Starts from: protein.md's evidence recipe, bounded identity follow-up, outside-in case table and measured budget section, with the 2026-10-26 protein rulings, which win over the design text; the j14202, j14211 and j14221 archives on the evidence store; the existing UniProt adapter in `crates/biomcp-adapters/src/uniprot/`.
- Rules: the recipe names each exact URL and each chosen query before the job runs, sends each row once in order with at least one second between requests, a 30-second deadline and a 4 MiB body bound, and makes at most twelve physical requests. No retry, redirect, altered query, fallback host or extra page. A 401, 403 or 429 stops that source. No credential, cookie, script crawl, whole proteome, InterPro match bundle or ComplexTab download. STRING is not called. A failed or empty witness keeps its capability deferred: without the five-hit page, the search ticket brings its ceiling back to the PM; without the unreviewed positive, `--include-unreviewed` stays deferred with a not-yet-supported message; without a proven second page, that source returns its first native window and labels the collection incomplete when the source says more exists, with no page step beyond the window; without the InterPro type selection, `protein domains --type` filters the complete retained collection locally; without the isoform entry get, `get protein` takes base accessions only and an isoform accession names `protein isoforms` and `protein sequence`; without the absent-record replies, absent versus failed rests on synthetic cases labeled synthetic. No biological or clinical answer is calculated from a capture.
- Proof: the job ledger records every attempt with its exact URL, status, headers, bytes, SHA-256, elapsed time, returned identifiers, native count and continuation, and the archive path and hash appear in protein.md beside each witness's result, and through pm progress. Each archive member is verified independently before unique scratch is deleted. A reviewer checks that each witness's result names the capability it unlocks or defers. No raw source body and no licensed content enters the repo. Then make landing-gate runs through pm job.
