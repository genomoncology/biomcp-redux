## Outcome

The existing GWAS Catalog v2 adapter in `crates/biomcp-adapters/src/gwas/` gains the association selectors, and `search gwas` returns a page of three association headers ordered by native p value ascending, with the order echoed in the query. `--variant rs2981582` selects by exact rsID; `--trait TEXT` sends the literal publisher trait text unchanged; `--trait-id MONDO_0004989` selects the exact mapped ontology ID, and `--include-child-traits` adds the native child-trait parameter and echoes it; `--gene FGFR2` selects by the publisher's mapped-gene definition, and `--extended-geneset` adds the native extended-gene-set parameter and echoes it; `--study GCST000035` selects the exact study; `--pubmed 17529967` selects the exact publication and keeps every study ID. Combined selectors go to the source in one request and use the source's own conjunction, as the FGFR2 plus MONDO_0004989 capture proved. `--limit` and `--offset` page natively, and a continuation keeps every selector and the order. The 0.9 positional query and `-g` work as `--gene`, and `-l` works as `--limit`. Each header carries the association ID, study accession, reported and mapped traits, effect alleles, exact p value and reported effect.

- Why: the first GWAS question asks which source associations match an exact variant, trait, gene, study or publication, and the GWAS rulings accept this command tree, the default page of three and native p-value-ascending order.
- Starts from: gwas.md's command tree, measured public-tier behavior and measured disclosure costs, with the GWAS rulings in `decisions/2026-10-26-protein-pathway-study-rulings.md`, which win over the design text; 0205's witnesses; the existing adapter's request identity check and `crates/biomcp-query/src/variant/gwas.rs`; the shared transport, cache, pool and next-step rules in `architecture.md`, including 6.10; 0230's types.
- Rules: one GWAS adapter, one transport, one terms declaration and one association decoder; the variant section keeps its ownership and its behavior. No v1 path, bundle or `sync gwas`. The restricted source category and the existing 15-second adapter deadline stay unchanged, including for the extended gene set. The 0.9 local intersection of two 50-row prefixes retires, and no combined request falls back to local intersection. Trait text is never expanded, and no label is matched locally to an ontology ID or gene. The adapter compares each reply's self link, page metadata and returned study, rsID, PMID or ontology identities with its checked request, and drops a mismatch with a problem and no cache admission. A page that starts between source page boundaries uses the existing offset rule. A successful zero stays a source-local empty page. Source order never implies clinical importance or causality. Next steps follow architecture 6.10: one association get per row before the continuation, then source-order distinct study, rsID and publication pivots within the bound, each from the source-given identity. Study metadata is never fetched once per search hit.
- Proof: outside-in cases first, watched to fail. Before adapter code, one bounded keyless pm job captures each case's exact request once, with zero retries, and records the replies. Q01 to Q05 assert the PMID 17529967 default page in order 6110, 6111, 6112 and its second page with 6113, 6114 and the rs981782 record kept; Q09 asserts PMID 17529974's two records for GCST000037; Q12 to Q14 assert PMID 18438407 as a successful zero with the gap kept visible; Q15 asserts association 5949 for PMID 17934461; Q18 to Q20 assert association 6063 with its source effect label; Q21 asserts association 11386 among GCST000057's seven; Q23 asserts rs113488022 as a successful zero; Q25 asserts the first rs2981582 page carries a continuation when the source reports further pages. Cases assert MONDO_0004989 without and with child traits as distinct totals, FGFR2 standard and extended gene sets as distinct totals, the FGFR2 plus MONDO_0004989 conjunction, rs2981582 plus PMID 17529967 returning only 6110, the trait text and study positives from 0205, the negative boundary for each selector, and a continuation that keeps every selector. Recorded 429, 500, timeout and broken-body cases assert a failed outcome with source and terms, never an empty page. The job measures each command in CLI and MCP output, starting from the projection ceilings of 2,496 bytes for the rs2981582 page, 2,390 for the PMID 17529967 page and 3,263 for the FGFR2 plus trait page, and each case gets a ceiling at measured size plus 15 percent, recorded in gwas.md. Real replies replay from outside the repo through `--cases DIR`, and synthetic replies prove failure mechanics. Then make landing-gate runs through pm job.
