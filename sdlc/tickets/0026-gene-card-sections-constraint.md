- PM decision: 2026-10-24. Sections follow architecture 8.2. Without `--section`, the trailing positional words that exactly equal a lowercase section word or `all` are sections, and the first positional word is always an input. `--section` takes one value and repeats; with it every positional word is an input. Matching is case-sensitive, because HGNC lists `ALL` as an alias of BCR (HGNC:1014): `get gene ALL` resolves BCR and `get gene BCR all` requests every section. One schema extension key on `section` marks it as the trailing positional set, so grammar.rs and spell.rs read the rule from the schema; spell.rs uses `--section` only when an input equals a section word. The query echo keeps the words as typed. The query layer expands `all` to every section in enum order and collapses repeats.
- PM decision: 2026-10-24. The response section enum holds only the sections that have landed, so this ticket adds `constraint`; each later section ticket adds its own word, its `GeneSections` field and its module. `all` is a query word, never a `more` value. `more` lists, in enum order, each section that was not requested and that the record's own facts do not rule out. `next` gains `StepKind::Section`: one step per resolved card, `get gene <HGNC ID> <every section in more>`, after fresh, sync and disambiguate steps, within the five-step cap.
- PM decision: 2026-10-24. `constraint` follows gene.md section 5: `Section<Constraint>` with `pli`, `loeuf` (gnomAD `oe_lof_upper`), `oe_lof`, `mis_z`, `syn_z`, `flags` when non-empty, `transcript` (the canonical transcript gnomAD returns) and `version: "v4"`. The version is BioMCP's statement that it asked the GRCh38 dataset, which gnomAD serves as v4 (gene.md section 3). Ask by HGNC's Ensembl ID, never by symbol. `NotApplicable` when the locus group is not protein coding or HGNC lists no Ensembl ID, with no request. A null `gnomad_constraint` or a null alias with `Gene not found` is `Empty` with no record. Any other GraphQL error fails the check as `bad_reply`.
