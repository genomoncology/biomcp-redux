# 1191 — mcp-protocol-2024-11-05

Milestone: 7

## Outcome

Over stdio, an MCP client that sends `protocolVersion` `2024-11-05` in `initialize` gets `2024-11-05` back, and can list and call tools; replies under that revision carry no field the 2024-11-05 specification does not define. Over HTTP, an `initialize` asking for `2024-11-05` gets HTTP 200 with a revision BioMCP supports, as lifecycle version negotiation requires, never a 400.

## Why

On 1.0 main (23d82a4c3), a stdio `initialize` asking for `2024-11-05` is answered with `2025-11-25`, because `REVISIONS` lists only `2025-03-26` and later. 0.9.3 answered `2024-11-05`, so this is a 1.0 regression (a public handshake report against 0.9.3 has a different cause). Apps built on the official TypeScript SDK 1.10.2 or earlier, or the Python SDK 1.8.1 or earlier, support only `2024-11-05` and fail the 1.0 handshake.

## Rulings

- `sdlc/decisions/2026-11-01-no-backwards-compatibility.md` line 9: the MCP protocol revisions BioMCP answers serve current clients of an outside protocol, and that ruling does not decide them. Adding a revision is not compatibility code for old BioMCP formats.

- The specifications: https://modelcontextprotocol.io/specification/2024-11-05 and https://modelcontextprotocol.io/specification/2025-03-26 (changelog).

## Decisions

- PM decision (2026-11-27): add `2024-11-05` after `2025-03-26`, so code that indexes the list keeps its meaning. The developer checks every use of `REVISIONS`.
- PM decision (2026-11-27): compare 2024-11-05 with 2025-03-26 from the specification's changelog. Any reply field that 2025-03-26 added, such as tool `annotations` or audio content, is left out for a 2024-11-05 session. Name each difference handled in the commit message.
- PM decision (2026-11-27, revised after MCP standards review): HTTP does not add 2024-11-05 (its transport is the old HTTP+SSE one). An HTTP `initialize` asking for it gets 200 offering a supported revision; requests after initialize that carry an unsupported `MCP-Protocol-Version` header keep today's refusal. The branch's `november_2024_refused` assertion of 400 on initialize is wrong.

## Keeps

- Keeps: replies under every revision already supported; the refusal of unsupported revisions.

## Proof

- Proof:
  - an outside-in stdio case where `initialize` with `2024-11-05` returns `2024-11-05`, then `tools/list` and one `tools/call` succeed with no 2025-03-26-only fields;
  - an HTTP case where `initialize` with `2024-11-05` returns 200 and a supported revision;
  - the HTTP test in `crates/biomcp/tests/runner/http.rs` that expects `2024-11-05` to be refused instead uses a revision BioMCP does not support, such as `2024-10-07`;
  - `make landing-gate`.

## Defers

- Defers: revisions older than 2024-11-05 (none are in use).
