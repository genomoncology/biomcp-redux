# 0172 — Sync the GTR bundle and search and get GTR laboratory tests

Status: OPEN.

Milestone: 4

Depends on: 0170
Depends on: 0171

## Outcome

`biomcp sync gtr` downloads GTR's `test_version.gz` and `test_condition_gene.txt`, validates both, checks exact accession and version multiplicity across the whole version report before any status filter, and replaces the local pair atomically with a `biomcp.sync/2` receipt that counts duplicate identities. `search diagnostic --source gtr` with `--gene BRCA1`, `--gene-id 672` or `--condition-id MedGen:C2676676`, optionally combined with `--type`, returns a five-row page of test headers from the stored bundle in source order with the native relation that matched, paged with `--limit` and `--offset` with every selector and the bundle revision kept. `get diagnostic GTR000006692.3 --source gtr` returns the exact test card, and `genes`, `conditions` and `methods` return the native relation pages with `--section-limit` and `--section-offset`. The conflicting `GTR000551465.2` shows once in search with a conflict status and no get step, and its get returns an identity-conflict problem and no card.

- Why: Q14 to Q18 ask which laboratory tests list a gene, and the design keeps the GTR bundle with exact field selectors and explicit conflict handling.
- Starts from: diagnostic.md's GTR rows, selector table, field lists, conflict policy, next-step table and case map, with the 0154 PM rulings and recheck amendments; the j12632 capture and its GTR findings; the shared `sync <bundle>` contract and stored-only bundle read API from 0131; 0170's types and 0171's registry.
- Rules: `--gene` matches the native `gene_symbol` field exactly, never `object_name`, a pipe substring or a synonym list. `--gene-id` matches a gene row's `gene_or_SNOMED_CT_ID` and is exclusive with `--gene`. `--condition-id` matches a condition row's `GTR_identifier`. `--type` matches the native `test_type` whole value. A gene relation never means a variant is assayed, and a listing never means FDA authorization or NIH endorsement. The object discriminator, namespace and value travel together. Native symbol and gene ID collections stay separate, and page totals say whether they count native rows or distinct IDs. Relation rows without a current card stay visible and are never inner-joined away. Reads never trigger a sync, and a failed validation keeps the old usable copy. No laboratory selector, no `--full` and no automatic disease or FDA call. Next steps follow diagnostic.md's table under architecture 6.10: a gene page gives `get gene 672` once per distinct NCBI Gene ID in source order, a label-only row gives no gene step, and no condition row gives a disease step without an exact supported namespace.
- Proof: outside-in cases first, watched to fail. Before adapter code, one bounded keyless pm job syncs the bundle once and records the receipt. Q14 asserts that `--gene BRCA1` and `--gene-id 672` select the same 433 tests (on the 2026-10-25 capture) and that the two selectors are exclusive; the condition case asserts `--condition-id MedGen:C2676676` selects `GTR000006692.3`; Q16 asserts `--type Clinical` and `--type Research` as distinct exact values and a conjunction with a gene selector; the broad panel `GTR000511179.13` asserts a complete walk of its genes and conditions pages with no gap or duplicate and its distinct row and ID counts; Q17 asserts `GTR000021517.11`'s bulk facts beside the unavailable web page; the conflict case asserts `GTR000551465.2`'s search row, get problem and a receipt count of one; Q18 asserts a synthetic zero as a source-local empty. Sync cases cover a synthetic partial download, a malformed member, a failed second file and two concurrent readers during one replacement, with zero requests on reads. Each case has a size ceiling from its measured CLI and MCP output, starting from the design's provisional ceilings of 391 bytes for a header, 1,962 for a page, 1,821 for the card, 1,344 for genes and 1,326 for conditions, with methods measured first. The full bundle stays out of the repo and replays from outside it through `--cases DIR`, and synthetic files prove sync mechanics. No licensed content enters the repo, and replies whose terms bar storage replay from outside the repo. Then make landing-gate runs through pm job.
