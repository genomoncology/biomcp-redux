# 0015 — Serve the existing commands through one stdio MCP tool

Status: OPEN.

Milestone: 1

## Outcome

BioMCP serves one stdio MCP tool that runs the existing schema/error command dispatcher, and real cases prove CLI and MCP return equal JSON results.

Depends on: 0013
Depends on: 0012

- Starts from: `sdlc/plan.md` stages 5 and 6; architecture sections 8.7 and 10.1–10.2; the official stable MCP specification when this ticket starts; config::schema_name, schema::find, output::{schema,usage}, exit::finish, runner Step/run_step, assertions::{prepare,check} and launch::Environment. Extract the general dispatcher from these boundaries; one does not exist yet.
- Changes: `crates/biomcp/src/main.rs`, `crates/biomcp/src/config.rs`, `crates/biomcp/src/mcp.rs`, `crates/biomcp/src/mcp/**`, `crates/biomcp/src/command.rs`, `crates/biomcp/src/output.rs`, `crates/biomcp/src/exit.rs`, `crates/biomcp/src/schema.rs`, `crates/biomcp/tests/runner/**`, `crates/biomcp/tests/cases.rs`, `tests/cases/schema/**`, `tests/cases/mcp/**`, `crates/biomcp/tests/ratchets/source.rs`.
- PM decision: 2026-10-24. Implement stdio MCP for existing schema commands and usage errors with the same dispatcher, pinned current stable spec revisions and parity cases. outputSchema covers only today's JSON object results; widen it with gene envelopes. No transport flags before a real transport command.
- PM decision: 2026-10-24. Support exactly current 2026-07-28 and legacy 2025-11-25, with one protocol-edge adapter per era and one command dispatcher. Architecture 8.7 records this ruling. Add no 2025-06-18 commitment.
- Scope: Extract argument interpretation and an outcome containing the JSON result and command status. CLI and MCP consume it directly; MCP never captures CLI stdout or launches a nested CLI. Process args remain at config boundary, CLI bytes/exits stay unchanged, and serve remains an entry action rather than a recursive tool command. Advertise exactly biomcp with required string-array args and additionalProperties false; outputSchema is {type:object}. Tool result structuredContent is the outcome object and text is its compact JSON; isError derives from status, not arbitrary payload fields. Output-write failures remain process failures, never fabricated tool outcomes.
- Protocol: Current requests use the pinned specification's required version/capability params._meta fields, mandatory server/discover and resultType complete. Modern requests work without prior discovery. Missing required metadata is -32602; unsupported version is -32022 with supported/requested data. Legacy initialize negotiates only the legacy list and falls back to 2025-11-25, never the modern version. Keep modern request metadata independent of legacy connection state. Use one declared revision list. Follow the official current/legacy versioning, tools and stdio specifications rather than copying older handshake assumptions.
- Validation: Parse error -32700, invalid object/array -32600, unknown method -32601, malformed params or unknown tool -32602. Preserve valid string/integer IDs; reject null/fractional IDs as the pinned MCP contract requires. Valid notifications are silent. Current cancellation marks active IDs cancelled and suppresses later results; ignore unknown/completed IDs and never echo a cancellation reason. Missing/nonstring args or extra tool-argument properties are protocol errors; invalid CLI commands in a valid list return the typed usage result.
- Lifecycle: Bound active threads, admitted messages, retained frames and completed worker handles in a few named code constants. Input does not wait for a tool slot or join a worker. Reject excess tool work with fixed nonreserved application code -31000; ping/discovery bypass admission. Serialize/write complete responses atomically under one writer, without executing commands under that lock. Read frames with bounded allocation, not unbounded read_line followed by a check. Oversized frames emit one fixed error then terminate; truncated EOF frames are malformed. Clean EOF stops admission and drains accepted calls. Broken output exits 5 with the existing fixed diagnostic even if stdin remains open; never join a permanently blocked input reader.
- Runner: run and mcp are optional argument lists, distinct from empty lists, with at least one required. Both use isolated Environment. Add is_error default false for MCP independently of CLI exit; paired usage cases set exit 2/is_error true. Always compare paired parsed results even without expect, and check text JSON equals structuredContent. Use the same assertions and application-result token/byte ceilings, excluding the RPC wrapper for MCP. Keep CLI byte ceilings on actual stdout. Protocol trials may drive the built server within the current target, without a generic protocol YAML language.
- Keeps: No MCP dependency or async runtime. Bound inbound message framing and worker admission in named code configuration, reject malformed messages with fixed diagnostics and avoid raw input in errors. Do not block input/output progress behind a slow tool call or mix interleaved responses. Keep current schema output and typed usage envelope; add a new public error variant only if an actual new path needs it. No replay/MCP-global flag promises, provider calls or unimplemented command grammar.
- Ownership: Record/replay lane 0014 owns root manifests/lock. This ticket adds no dependency and owns binary/runner files. Correct narrow Claims if a shared dispatcher helper is needed; do not edit transport files.
- Proof: Actual built-server cases exercise both pinned eras, modern discovery/metadata/unsupported version, legacy fallback, one tool, schema/usage parity, malformed args/tool, silent notifications via a following correlated ping/EOF, and complete correlated concurrent string/integer-ID replies. Negative selected runner cases prove MCP assertions/ceilings/is_error and unequal successful results fail parity. Prove artifact-based discovery, EOF draining and broken stdout while stdin stays open; kill/reap a genuine hang with a generous watchdog rather than timing success. Malformed/oversized distinctive payloads never appear in diagnostics. Preserve existing filter/isolation/broken-output cases and run make landing-gate through pm job after main.
- Defers: Deterministic slow-command scheduling proof waits for a real delayed provider/replay consumer; add no fake slow command or product hook. Entity request grammar, normal envelopes, replay/server flags and live-data MCP cases arrive with their real consumers. The one-tool roadmap item can be ticked only when the accepted actual tool/CLI grammar contract is satisfied; no broad output/runner item is completed by this ticket alone.
