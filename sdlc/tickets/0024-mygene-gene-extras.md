# 0024 — Fetch gene summaries and spans from MyGene.info

Status: OPEN.

Milestone: 1

## Outcome

The MyGene.info adapter returns, for a batch of Entrez IDs, each gene's whole RefSeq summary with its stated date, its GRCh38 and GRCh37 spans with strand, and the HGNC and Entrez IDs that let the caller check the join, with unknown IDs absent and bad fields as problems, proven by replay of a recorded reply.

- Checked boundaries, 2026-10-24: `POST https://mygene.info/v3/gene` with form fields `ids=673,1438,999999999`, `fields=summary,genomic_pos,genomic_pos_hg19,HGNC,entrezgene` and `species=human` returned 200 `application/json; charset=UTF-8` with a JSON array of one hit per ID in request order. BRAF's hit is `{"query":"673","HGNC":"1097","entrezgene":"673","genomic_pos":{"chr":"7","start":140719327,"end":140925199,"strand":-1,"ensemblgene":"ENSG00000157764"},"genomic_pos_hg19":{"chr":"7","start":140419127,"end":140624564,"strand":-1},"summary":"… [provided by RefSeq, Aug 2017]."}`. Its summary is 809 characters and contains `V600E`. `HGNC` and `entrezgene` are strings. CSF2RA (1438) has a two-item `genomic_pos` list on X and Y and a single `genomic_pos_hg19` object. An unknown ID returns `{"query":"999999999","notfound":true}`.
- Reviewed source boundaries: The official batch maximum is 1,000 IDs; BATCH=200 is a local choice. No published numeric rate was found, so declare conservative local biothings policy of one request per second/one in flight, without claiming a provider limit. Official error objects are HTTP400/404; a copied HTTP200 error object is synthetic malformed input. Sources: https://docs.mygene.info/en/latest/doc/annotation_service.html#batch-queries-via-post and https://docs.mygene.info/en/latest/doc/response_status_codes.html .
- PM decision: 2026-10-24. Query by Entrez ID only, never by symbol, as gene.md says. Declare `post_form("/gene").idempotent().fresh(Freshness::Days(7))`, because the call reads and never changes state. HGNC owns every cross ID (gene.md field ownership). `GeneExtras { entrez_id, hgnc_id, summary, spans }` lives in the adapter crate, and 0025 uses `hgnc_id` only to check the join, never to print. The summary keeps its text whole and moves the trailing `[provided by RefSeq, Mon YYYY].` into `Summary.dated` with `SummarySource::RefSeq`. A summary without that marker keeps its whole text and RefSeq attribution with no date. `genomic_pos` maps to GRCh38 and `genomic_pos_hg19` to GRCh37 (0021's cited MyGene.info notice). Every listed position becomes a span, so CSF2RA keeps both X and Y. Strand 1 maps to forward and -1 to reverse, an absent strand stays absent, and any other value or bad bounds drop that span with a problem. A `notfound` hit is absent. Two hits for one query drop that ID with a problem and never pick one.
- Scope: mygene/mod.rs holds SPEC, endpoint, FIELDS, BATCH and genes(leg,ids). Sort/deduplicate IDs then chunk through Leg::batch. Return Vec<GeneBatch>, where GeneBatch { ids: Box<[EntrezGeneId]>, result: Result<Vec<Mapped<GeneExtras>>, RequestError> } retains IDs affected by each chunk failure. Raw Genes/Hit/Pos use OneOrMany without serde(default); Reply::check rejects non-array or missing query. Correlate by query, never position/_id. Every query belongs to its submitted chunk; duplicate hits drop that query with a problem. Notfound is absence. GeneExtras retains submitted query ID separately from returned Entrez and optional HGNC; mismatched/missing identities never attach extras to an HGNC-owned record. map.rs preserves mapping Problems.
- Keeps: Adapter rules in architecture 5.6. No symbol query, no NCBI or Ensembl call, no merge with HGNC fields, no card or command, no new dependency, and adapter files under 300 lines.
- Proof: Capture the checked request once with Mode::Record from an uncommitted local driver into `tests/replies/mygene/`. Under the 2026-10-24 PM decision that 0023 also records, adapter contract tests are allowed until 0025's cases cover them and 0025 deletes the duplicates. `crates/biomcp-adapters/tests/mygene.rs` replays it with no network. It proves BRAF's reverse GRCh38 Span0 [140719326,140925199) and GRCh37 [140419126,140624564), converted by the cited source-chain rule. It proves the summary text containing `V600E` with dated 2017-08 and no bracket marker, HGNC:1097, both CSF2RA GRCh38 spans and an absent 999999999. Small hand-edited copies prove a bad strand, inverted bounds and a duplicate hit becoming problems, and a reply without `query` failing as bad_reply. A two-chunk batch keeps a failed chunk from hiding the other. Then make landing-gate runs through pm job after current main.
