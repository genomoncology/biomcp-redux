# 0242 — Retire old phenotype forms and prove phenotype failure and pairing cases

Status: OPEN.

Milestone: 4

Depends on: 0220
Depends on: 0240

## Outcome

Every 0.9 phenotype command and option that phenotype.md drops, renames or defers returns a fixed usage error that names the supported route or the reason, and makes zero requests. The 0.9 `search phenotype` form with a space or comma separated set of HP IDs returns a fixed retirement message that names `search phenotype TEXT` and the `diseases` and `genes` sections of `get phenotype HP:ID --source monarch`, in place of the disease slice's ranking message. Every source and section pairing outside 0211's list fails before I/O. HPO and Monarch each report a failed outcome, never an empty one, on a 429, 500, timeout, broken JSON or HTTP 200 error body, and a mismatched returned identity, an off-namespace search item or a wrong-taxon gene row is rejected with a problem and never enters the cache.

- Why: the PM rulings defer Monarch similarity and give the HP ID set form a fixed retirement message, phenotype.md's accounting retires or renames the other 0.9 forms, and the slice rules require failure and identity cases for every adapter.
- Starts from: phenotype.md's legacy accounting and error and cost cases, with the Phenotype rulings in `2026-10-26-protein-pathway-study-rulings.md`; `crates/biomcp/src/retired/disease.rs` and `crates/biomcp-types/src/response/error.rs`; the disease D13 and D14 retired ranking cases; the adapters from 0217, 0220 and 0240.
- Rules: an HP ID set is the only `search phenotype` form that retires, and literal text with commas stays a term search. The disease retired ranking cases move to the new message. `list phenotype` names `help phenotype`. The 0.9 automatic HPO resolution, similarity window, per-term direct-support states and automatic first supported disease step have no 1.0 option, so no flag is invented to retire them. `search phenotype --source hpo` says HPO term search has no proved paging contract and names `--source monarch`. The pairing failures are: `hierarchy`, `diseases` or `genes` with `--source hpo`; `xrefs --source monarch` unless 0208 proved a positive Monarch xref; a MONDO, gene or malformed identifier on `get phenotype`; and an omitted `get phenotype` source unless the PM has ruled a default. Zero, overflow and out-of-range `--limit`, `--offset`, `--section-limit` and `--section-offset` fail before I/O. No retirement rewrites the query or picks a candidate.
- Proof: outside-in cases first. A case per retired form and per pairing failure asserts its message with zero provider requests. Synthetic 429, 500, timeout, broken JSON and HTTP 200 error replies for `hpo` and `monarch`, labeled synthetic, cover search, each card, a text section and an association section, and assert a failed outcome with source and terms. Synthetic replies with a wrong returned HP ID, an MP or UPHENO search item and a non-human gene row assert the rejection, the problem and no cache admission. P24 asserts that a successful empty search, the absent `HP:9999999` and a source failure are three distinct states with no clinical absence claim. Disabled `hpo` and `monarch` cases under `--fresh` assert the skip before any cache read. Each case has a size ceiling. This ticket adds no filter or exact-ID get and makes no provider call; the filters and exact-ID gets it relies on have known-positive captures through one bounded keyless pm job in 0208, 0217, 0220 and 0240. No licensed content enters the repo, and replies whose terms bar storage replay from outside the repo. Then make landing-gate runs through pm job.
