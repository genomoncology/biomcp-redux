# 0138 — Add the disease types and generated schemas

Status: COMPLETE.
Landed: 7858544e18f537ff84270008ddd08f7b01be1095

Milestone: 3

## Outcome

`biodata` holds the neutral disease records that `planning/slices/disease.md` names: a source association record for disease gene and phenotype rows and a statistics record for native SEER rows, both reusing the shared `Curie`, `Concept` and `Attribution`. `biomcp-types` holds the consumer side: the `search disease` request with positional text, `--source`, a closed `--ontology` set of `mondo`, `doid` and `ncit` with `mondo` as its default, `--limit` and `--offset`; the `get disease` request with an ID, `--source`, `--ontology` for OLS, the named sections `synonyms`, `xrefs`, `hierarchy`, `genes`, `phenotypes`, `incidence` and `survival`, and `--section-limit` and `--section-offset`; the SEER selectors `--sex`, `--race`, `--age-range`, `--dataset`, incidence-only `--period` and survival-only `--interval`; the candidate header, the exact-ID card, the section pages, the SEER site catalog page and the incidence and survival pages. The generated, checked-in schemas are `biomcp.disease_page/1`, `biomcp.disease_card/1`, `biomcp.disease_synonyms/1`, `biomcp.disease_xrefs/1`, `biomcp.disease_hierarchy/1`, `biomcp.disease_genes/1`, `biomcp.disease_phenotypes/1`, `biomcp.disease_sites/1`, `biomcp.disease_incidence/1` and `biomcp.disease_survival/1`.

- Why: the slice method lands types and schema before adapters, and the accepted disease design with the 0117 PM amendments of 2026-10-25 fixes the identity model, the command tree and the page shapes.
- Starts from: disease.md's settled product contract, command table, proposed JSON and case map, with the 0117 recheck amendments, which win over the design text; `rust-standards.md`; the shared `Curie`, `Concept` and `Attribution` in `crates/biodata/src/variant/statement`; `ComponentTerms` and the framing types in `biomcp-types`.
- Rules: no `DiseaseId` and no second ontology identity type. MONDO, DOID, NCIt, OncoTree and each ICD edition stay distinct namespaces. A label, scoped synonym, parent edge, cross-reference, close match and exact match are distinct facts that keep their publisher predicate, version and provenance. Associations are records, never `Statement` values, and keep source subject, object, predicate, original IDs, evidence and qualifiers. Every association row carries the requested ID beside its returned subject and object, and a row total counts association rows, never unique genes. A statistics row keeps requested selectors beside returned selectors, a missing value stays absent, and observed and modeled values stay separate fields. The card carries identity, a complete optional definition, obsolete, consider and replacement facts, component terms, available sections and next steps, and no association, statistic or related-entity field. `--ontology` accepts exactly one value, and any other name or a comma list fails before I/O. `-l` and `all` do not exist. The survival request has no `--period`. A SEER get takes a site ID and refuses an ontology CURIE. `--section-limit` and `--section-offset` are the only get-level paging spellings.
- Proof: cases first. Round-trip tests for each closed set and each ID form, including refusal of an unknown ontology and of a SEER request with a CURIE; a test that the card type has no association or statistics field; a test that association records cannot become a `Statement`. D02-help asserts the generated help lists the typed command tree, D02-format-parity asserts `--format md` and `--format json` carry the same facts over a synthetic page, and D05-retired-multi-ontology asserts `--ontology mondo,doid` fails before I/O with guidance to name one ontology. The generated schemas are checked in with snapshot and compatibility checks, and existing schemas stay unchanged. This ticket adds no filter or exact-ID get and makes no provider call; each filter and exact-ID get that later disease tickets add has a known-positive capture through one bounded keyless pm job. No licensed content enters the repo, and replies whose terms bar storage replay from outside the repo. Then make landing-gate runs through pm job.
- PM ruling 2026-10-25: proof stays inside the type boundary, as 0124 did: standalone public request and schema option metadata and synthetic serialization. Existing request, step and envelope schemas stay unchanged. Executable D02 help and Markdown parity move to 0140, which registers disease in the shared request and takes those schemas' version changes.
