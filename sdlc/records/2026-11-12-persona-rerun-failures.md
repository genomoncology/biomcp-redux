November 12, 2026. The bench 0040 persona rerun (biomed-agent-bench `personas/rollup.md`, "BioMCP failures from the new runs") listed 25 BioMCP failures from runs on BioMCP df79ecb50. Each was run again live, from the exact command in the cited `personas/<slug>/runs/2026-11-12b/log.md` line, on:

- current main `59150d16db38daa2490bca27657851ba6b7f20ca` (0861, generic label get prefers the current label; main when this work started; 0862's CIViC fix landed later as 22eb8065f and was not used),
- df79ecb50 (the build the personas ran),
- 58d83b6da (the 0037 build), to check the four suspected regressions.

Evidence: pm job j38804 (ticket key 0866, M5; builds and all cases on the three commits plus the source API checks, cancelled once the three runs were done because the per-commit probe stage could add nothing) and j38812 (follow-up: FDA SSED downloads and a few extra probes). Case labels below ("case 2b") are the `###` blocks in those job logs (`pm job log j38804 --all`, `pm job log j38812 --all`); a bare case label means j38804. Where the persona's own reply was in doubt, the run's full call record was read on the M5 in `~/workspace/data/biomed-agent-bench/0040-persona-<slug>/biomcp-cli/calls.md`.

## Regressions asked about

None of the four is a regression.

- (a) Label sections cut at about 6 KB: not a bug. Label text is paged in 6,144-byte fragments, unchanged since before 0037 (`crates/biomcp-adapters/src/openfda_label/page.rs`, last changed in 777fdacd5). On main, df79ecb50 and 58d83b6da alike, `warnings_and_cautions` returns fragment 0 of `total 4` with a `next` step to `--section-offset 1` (case 1a); `adverse_reactions --section-offset 1` returns the next fragment, offset 1 of 30 (case 1c); openFDA's own field is 19,705 characters, so four fragments is right. Following the `next` steps on main, fragment 2 contains "myocarditis" and fragment 3 ends with `next: null` (j38812 cases 1-w&c-off1 to off3). The pv-scientist agent printed only `result.label` (first 2,500 characters) and, for the offset call, only the first 400 bytes of the reply (`calls.md` lines 3209 and 3915), so it never saw `total` or `next`.
- (b) Population `--detail` lost its ancestry groups: not a bug. On all three commits the reply carries `result.groups` with 29 rows, 10 a page (case 5), matching gnomAD's own 29 exome populations. The tumor-board agent looked for `result.population.data.groups` (`calls.md` lines 2624-2640) and found nothing there. Without `--detail` there are no groups (j38812 case 5), as documented.
- (c) cBioPortal recurrence counts per page: by design, unchanged since before 0037 (`crates/biomcp-query/src/variant/recurrence.rs:82`, `all_pages_read = page == 0 && !more`; the schema says "on this source page only"). Pages 0-3 give 36, 34, 43 and 15 samples (case 4p0-4p3), which sum to 128, the same as cBioPortal's own API (128 distinct samples with the exact allele among 355 PIK3CA rows). In 0037 the agent used `--limit 1000` and got 128 with `all_pages_read: true` in one call (tumor-board `runs/2026-11-12-capped-2usd/log.md:101`); main does the same today (j38812 case 4-limit1000: observed 128, examined 355, `all_pages_read: true`, `more: false`).
- PMA summaries refused: not a code regression. No code in the PMA, PDF or fetch paths changed between 58d83b6da and main. The 0037 build fails the same way today, and on that run even P120019, which main and df79ecb50 read minutes earlier, came back `rejected` (j38804 case 3f on 58d83b6da). BioMCP turns any 4xx from accessdata.fda.gov into `reason "rejected"` (`crates/biomcp-adapters/src/pdf/download.rs:21-27`). The 4xx is FDA's abuse detection: in j38812 a plain curl GET of every SSED PDF (P170019B, P190032B, P150044B, P150013B, P240010B, P120019B) was redirected to `https://www.accessdata.fda.gov/apology_objects/abuse-detection-apology.html` with a 404, while the same GET with a browser user agent returned 200 and the PDF (198 KB to 1.3 MB). In the same job BioMCP read P170019 (58 pages, 27 fragments), P190032 (60 pages, 28 fragments) and P120019 on every try. So the refusals come and go with FDA's bot detection, and BioMCP reports them as a bare `rejected`.
