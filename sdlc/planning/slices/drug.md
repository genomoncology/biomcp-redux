# Drug slice investigation and proposed design

This design starts from `ecef1096239f8aeee8fcc6cbefc5720e89506035` and follows steps 1 to 4 of [the slice method](../slices.md). It serves cancer-care drug identity, authorization, label, target, biomarker-evidence and interaction questions. It proposes retrieval of attributed source facts. It authorizes no treatment interpretation, product code, new public service, or release. The PM reviews this design before filing implementation tickets.

## 2. Source findings and identity

The request plan uses twelve generic names, each shared by two clinical questions, plus Gleevec, Herceptin and Enhertu as brand identity controls. Each applicable source receives its own declared query; sources do not share an invented universal search language. A source that supplies no join identifier stays unjoinable. Source request identities, retrieval dates, bodies, byte counts, hashes and timings remain in the external evidence manifest. Reused bodies are local delivery of those original captures, not fresh provider responses.

### Identity contract

The clinical reviewer distinguishes ingredient, precise ingredient/salt, clinical drug/formulation, branded product, label SPL set/version, NDC package, FDA NDA/BLA, EU product/authorization and orphan designation. Preserve all those source-qualified levels. An explicit source identifier relation can connect them; a substring, antibody component, suffix removal, inferred salt equivalence or first search hit cannot.

A name search returns candidates with their native IDs, names, source and identity level. A source-qualified exact get verifies the returned ID before admitting the body to the cache. It never selects an ambiguous name. Source cross-references are attributed relations, not an unconditional union of records. Nonchemical therapies such as Yescarta may have no structure-based ID. D04 and D10 require separate product/formulation records even where ingredient components overlap. A changed identity answer requires fresh clinical review.

## 3. What would delight the agent

1. **First question.** `search drug Keytruda` returns source-ranked candidates and exact next commands. An exact source ID goes to `get drug ID`. The request echoes the chosen source and literal query.
2. **Smallest useful header.** Native name, identifier namespace, identity level, source, known parent ingredient/product links, and attributed authorization events with jurisdiction, event type and date. Missing authorization evidence remains unavailable, rather than becoming an unapproved flag.
3. **Next steps.** Typed `next` commands name candidate selection, approvals, boxed warning, dosing, other label headings, targets, indications, molecular-profile evidence, interactions, regulatory details and source-local continuation. Do not print a section until the measured tier supplies its fields.
4. **Exact identifiers.** Return ChEMBL, UNII, source molecule IDs, SPL set/version, application/product numbers, EMA product numbers, orphan IDs, evidence and molecular-profile IDs where actually supplied. An ingredient ID never replaces a package ID.
5. **Disagreement.** Print independent attributed claims, date roles, jurisdiction and source timestamps. D06's conflicting EMA dates survive. D23's old positive application record survives alongside the authoritative withdrawal event; neither silently overwrites the other.
6. **Empty versus failure.** Distinguish empty, error, partial, unsupported, missing join ID, missing bundle, stale bundle, disabled source and missing key. A missing interaction row is not evidence of safety.
7. **Cold and warm cost.** Measure source retrieval separately from local bundle lookup and offline output rendering. A warm identical request should make no new request. No fabricated common latency or cache speedup fills an unmeasured cell.
8. **What 0.9 gets wrong.** Inventory every option and section; retain only behaviors supported by these questions and measured fields. Remove free-text mechanism token expansion, local relevance ranking and chemical-name guessing under the accepted no-text-heuristics decision.
9. **Stopping early.** A small identity card answers D01/D03/D21 only when it carries the necessary explicit source relation. A default card does not embed full labels, all evidence rows, every interaction or pharmacogenomic screens.
10. **Clinical trust.** Every fact needs its source record, retrieval timestamp and available revision. Label warnings retain their indication-specific context. Native claims do not become treatment advice, eligibility judgments or a computed approval consensus.

## 4. Proposed types, schema and commands

These are design names, not implemented contracts. `biodata` owns neutral identifiers and domain records without I/O or consumer imports. `biomcp-types` owns requests, queries, source selection, envelopes, paging, cards, sections, caps and typed next steps. Reuse existing checked strings, dates, URLs, identifiers, attribution, section outcomes and source-policy labels. Generate schema from those types rather than copying field tables into a second registry.

Proposed domain records are `DrugIdentity`, `DrugIdentityRelation`, `DrugProduct`, `AuthorizationEvent`, `OrphanDesignation`, `DrugLabelReference`, `DrugLabelSection`, `DrugTargetRelation`, `DrugIndicationClaim` and `DrugInteractionClaim`. Each keeps source-native identifiers and terminology. An authorization event includes jurisdiction, event kind, native status, event date and its role, indication and document reference where the source sends them. Never infer current status from a historical date. Interaction claims preserve source severity, mechanism and management text separately; they do not derive scores. Reuse molecular-profile evidence structures where semantics match, preserving therapy combinations and profile membership.

| Proposed command | Default disclosure | Named deeper disclosure |
| --- | --- | --- |
| `search drug TEXT --source SOURCE` | One bounded page of native candidate headers, total/cursor where given, source order, exact query and actions | Next source page; explicit source selection. A fold, if kept, uses stated layout and independent totals, never a score blend. |
| `search drug --target ID --source SOURCE` | Native target–drug relations with exact source IDs | Source mechanisms, evidence and native continuation. Accept a gene symbol only where the source explicitly defines that selector. |
| `get drug SOURCE:ID` | One checked identity card with bounded source links and optional attributed native authorization summary | `approvals`, `regulatory`, `label`, `targets`, `indications`, `civic`, `interactions`, `shortage` only after tier proof. |
| `get drug SOURCE:ID label --label-section SOURCE_HEADING` | One complete selected native heading plus revision and parent identity | Other source headings and bounded text chunks with continuation. Boxed warning and dosing are distinct named requests. |
| `drug interactions SOURCE:ID` | One bounded page, native partner IDs/severity, total and bundle revision/freshness | Subsequent source-local page; exact partner/source row. No absence-of-risk claim. |
| `drug sync --source SOURCE` | Explicit local bundle replacement receipt with source URL, hash, size, version/retrieval date and terms | Validate all required files before replacing a previous usable bundle. No hidden refresh during get/search. |

Region means an explicit regulator or dataset selection, not a locally inferred geography. The design recommends source selection over 0.9's implicit multiregion fan-out. A source's own matching rules may supply candidates and aliases; the product adds no synonym lists, stemming, substring identity or query alteration. The query layer owns fixed echoed construction. The adapter maps the raw reply once. Shared transport owns quota, deadline, retries, body limits, recording, replay, decoding and admission checks. A local bundle follows the existing bundle endpoint shape and atomic synchronization recipe, not a drug-only cache or global download manager.

### Structural risks and outside-in cases

The main risks are restated identifier mappings, inferred product merges, stale positive approval records, unshared bundle replacement, and proving a hand-written projection rather than the shipped artifact. Keep each source mapping in its owning adapter, generate schemas/help from one contract and compare returned IDs before cache admission. Pin outside-in cases to D01–D24 and the actual source requests; add actual empty/failure plus synthetic 429, timeout, broken JSON and mismatched identity. Each filter needs its own source-native known-positive capture. A field absent from the public tier makes its section unsupported, rather than an empty list. Two concurrent readers and one bundle replacement must observe a complete old or new batch. Installed-package proof belongs to implementation/release work, not this investigation.

### Decisions for PM review

| Question | Options and trade-offs | Recommendation |
| --- | --- | --- |
| Should a name get choose a product automatically? | Convenient first-hit guessing loses identity; candidate search requires one explicit choice. | Require a source-qualified ID after candidate search. Keep ingredient and branded product identities distinct. |
| Should old region defaults fan out automatically? | Preserves old spelling but hides requests and mixes regulator scopes; explicit source selection exposes cost and meaning. | Make source explicit and use typed next commands for other regulators. The PM must rule on migration wording. |
| Should full label text live in a default card? | One large call can answer everything but buries current safety wording and grows output; named native sections keep complete context reachable. | Keep a small card, separate warning/dosing headings and complete continuations. Never summarize clinical text with heuristics. |
| Should DDInter remain available despite noncommercial terms? | Removing it loses structured interactions; keeping it requires honest component rights and caller policy. | Keep it one explicit section away if capture proves useful rows, enabled by default with its terms and normal disable groups. This design files no downstream tickets. The PM owns final command/product rulings and implementation order. No live source outage authorizes refresh loops, altered queries or inferred clinical facts.
