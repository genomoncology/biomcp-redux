# Release channels

BioMCP 1.0 keeps every 0.9 distribution name. GenomOncology owns publication for all channels. Its release operator publishes only after Ian approves the release. Local artifact production grants no permission to upload, deploy, change a registry entry or move a release pointer.

| Channel | Artifact and platforms | Publisher and destination | How a 0.9 user moves |
| --- | --- | --- | --- |
| PyPI `biomcp-cli` | Platform wheels containing the native executable for Linux x86_64 and arm64, macOS x86_64 and arm64, and Windows x86_64. | GenomOncology's PyPI release operator publishes `biomcp-cli`. | Upgrade the same package with the existing package manager. Both `biomcp` and `biomcp-cli` launch the installed executable. Keep `serve` in stdio client configuration. |
| `https://biomcp.org/install.sh` | Download installer and checksummed native release archives for Linux and macOS on x86_64 and arm64, and Windows x86_64 through MSYS, MINGW or Cygwin shells using its ZIP archive. | GenomOncology's site and GitHub release operator publishes the installer and archives to the existing site and `genomoncology/biomcp` release. | Rerun the installer for the approved version in the existing install directory. Retain the public download interface. `release/install.sh` retains the supplied archive, checksum and destination invocation and the public `--version` and environment interface. It selects the platform archive, downloads its checksum, verifies it and installs the executable. Windows shells select the ZIP. The release base URL can select a local mirror for isolated download checks. |
| Homebrew `biomcp` | Formula in `genomoncology/homebrew-biomcp`, selecting a checksummed macOS arm64 or x86_64 archive. | GenomOncology's tap release operator updates the existing tap after the archives are public. | Keep the existing tap and run `brew upgrade biomcp`. The local producer's file URL is a rehearsal input; the published formula must use release URLs. |
| GHCR `ghcr.io/genomoncology/biomcp` | Container image for Linux amd64 and arm64. | GenomOncology's container release operator publishes the version tag and moves `latest` only after release approval and both platform checks. | Pull the approved version from the same image name. The image entry point remains `biomcp`; use `serve` for stdio or the approved HTTP arguments. |
| Desktop extension `biomcp` | Platform-specific `.mcpb` archive containing `manifest.json` and the matching native executable. Preserve the existing macOS and Windows platforms. The local producer can also create a Linux bundle; that does not establish desktop client support. | GenomOncology's desktop extension release operator supplies the bundles to the existing directory or manual installation channel. | Update the extension through its existing distribution path. The manifest still starts the bundled executable with `serve`. Replace old per-tool client bindings with the single `biomcp` tool. Reconfigure credentials using the upgrade note. |
| MCP registry `io.github.genomoncology/biomcp` | Versioned `server.json` selecting the `biomcp-cli` PyPI package and stdio `serve`. Platforms follow the published wheels. | GenomOncology's registry release operator updates the existing entry after the matching wheels are public. | Refresh the same registry entry. Keep the package identifier and `serve` argument. The registry-selected executable and normal CLI use the same executable bytes. |
| Claude Code plugin `biomcp` | Plugin in the `genomoncology/biomcp` marketplace whose MCP entry starts the installed `biomcp serve` and ships the 1.0 skill guide. | GenomOncology's plugin release operator updates the existing marketplace entry after the release archives are public. | Update the plugin from the same marketplace. Replace old per-tool bindings with the single `biomcp` tool. |

## Artifact checks

The channel producers live in [release/](../../release/), [manifest.json](../../manifest.json) and [server.json](../../server.json). They derive versions from Cargo and retain the distribution names and platform families above.

`make release-artifacts` builds local artifacts without publication. The install gate exercises the wheel, supplied-archive and local-server download installer, local formula where Homebrew exists, container, desktop manifest command and registry-selected package command outside the checkout. It checks the installed executable, MCP lifecycle, replay and concurrent ordinary-cache use. Results identify unavailable native platforms and Homebrew explicitly. Generated manifests and cross-builds do not establish native platform execution.

The installer verifies archive checksums and extracts Windows ZIP archives in supported shells. Published formulas select release URLs. Versioned releases remain available when a new release replaces the channel's current version.

Read the [0.9 upgrade note](upgrade.md) before changing client configuration. Its generated command list comes from the same slice accounting as the roadmap ledger. `make docs-check` rejects drift in either generated view and rejects a deferred or dropped leaf that appears in the generated command reference.
