BioMCP <Fact k="version" /> reads one JSON configuration file and the environment. This page sets a source key; [write config.json](/getting-started/api-keys/config-file/) covers the other settings. None of it is needed for a first run.

## Where the configuration lives

| Platform | File |
| --- | --- |
| Linux and macOS | `$XDG_CONFIG_HOME/biomcp/config.json`, or `~/.config/biomcp/config.json` when `XDG_CONFIG_HOME` is unset |
| Windows | `%APPDATA%/biomcp/config.json` |

`--config PATH` reads another file for one command. `biomcp version --verbose` prints the file BioMCP uses.

## Set a key

BioMCP accepts <Fact k="counts.keys" /> keys. List them and their state:

<Example id="key-list" />

`biomcp key set SOURCE` asks for the key at a prompt that hides your typing, or reads one line from standard input. It stores the key in `config.json` and keeps it out of your shell history. `key list` reports names and states, never values. This run uses a throwaway file and a placeholder value:

<Example id="key-set-demo" />

BioMCP also writes an empty `.config.lock` file beside a configuration file it changes; the run removes both. The stored key is plain text in `config.json`. BioMCP writes the file readable by your user only (`-rw-------`); protect it like any other secret. The state is `stored` for a key in the file, `environment` for a key in its environment variable, and `none` otherwise. `biomcp key remove SOURCE` deletes a stored key. Setting a key that is already stored needs `--replace`.
