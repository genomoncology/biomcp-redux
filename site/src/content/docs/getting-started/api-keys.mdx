BioMCP <Fact k="version" /> reads one JSON configuration file and the environment. This page sets a source key, then covers every setting in `config.json`. None of it is needed for a first run.

## Where the configuration lives

| Platform | File |
| --- | --- |
| Linux and macOS | `$XDG_CONFIG_HOME/biomcp/config.json`, or `~/.config/biomcp/config.json` when `XDG_CONFIG_HOME` is unset |
| Windows | `%APPDATA%/biomcp/config.json` |

`--config PATH` reads another file for one command. `biomcp version --verbose` prints the file BioMCP uses.

## Set a key

<Fact k="counts.keys" /> sources accept a key. List them and their state:

<Example id="key-list" />

`biomcp key set SOURCE` asks for the key at a prompt that hides your typing, or reads one line from standard input. It stores the key in `config.json` and keeps it out of your shell history. `key list` reports names and states, never values. This run uses a throwaway file and a placeholder value:

<Example id="key-set-demo" />

The state is `stored` for a key in the file, `environment` for a key in its environment variable, and `none` otherwise. `biomcp key remove SOURCE` deletes a stored key. Setting a key that is already stored needs `--replace`.

`biomcp help key SOURCE` names the configuration field and the environment variable:

<Example id="help-key" />

| Source | Key name | Environment variable | Needed? |
| --- | --- | --- | --- |
| OncoKB | `oncokb` | `ONCOKB_TOKEN` | Required for OncoKB sections |
| NCI Clinical Trials Search | `nci` | `NCI_API_KEY` | Required for `--source nci` |
| NCBI (PubMed, PMC) | `ncbi` | `NCBI_API_KEY` | Optional; raises the rate limit |
| Semantic Scholar | `semantic-scholar` | `S2_API_KEY` | Optional; raises the rate limit |
| ORCID | `orcid` | `ORCID_ACCESS_TOKEN` | Optional |
| openFDA | `openfda` | `OPENFDA_API_KEY` | Optional; raises the rate limit |

Get each key from its publisher under the publisher's terms. A source that needs your key sends no request without it and reports `skipped` with reason `no_key`.

## Settings in config.json

| Setting | Type | What it does |
| --- | --- | --- |
| `format` | `"json"` or `"md"` | Default output format. `--format` overrides it. |
| `disable_sources` | list of source or group names | Sources and use groups to turn off. Combines with `--disable-sources`. See [data sources](/sources/#turn-sources-off). |
| `proxy` | URL | An HTTP or HTTPS proxy for every request. Overrides `HTTPS_PROXY` and `HTTP_PROXY`. |
| `ca_bundle` | path | A PEM file of extra certificate roots, added to the platform's trust. Verification stays on. |
| `http.allowed_hosts` | list of host names | Host names a non-loopback HTTP server accepts. See [run as a server](/getting-started/remote-http/). |
| `ncbi_email` | email address | Sent to NCBI with PubMed requests. |
| `keys` | object | Stored keys. Write them with `biomcp key set`. |

A commercial user's configuration, for example:

```json
{
  "format": "md",
  "disable_sources": ["noncommercial", "restricted"]
}
```

## Company networks

Without `proxy`, BioMCP reads `HTTPS_PROXY`, `HTTP_PROXY` and `NO_PROXY` from the environment. `NO_PROXY` bypasses exact hosts and IP addresses, `.domain`, `*.domain`, optional ports, or `*`. A network that inspects TLS needs its root certificate in `ca_bundle`:

```json
{
  "proxy": "http://proxy.example.com:3128",
  "ca_bundle": "/etc/ssl/certs/company-root.pem"
}
```

`biomcp help network proxy` and `biomcp help network ca_bundle` print the same rules.
