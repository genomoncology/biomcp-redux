BioMCP <Fact k="version" /> runs as an MCP server with `biomcp serve`. It offers <Fact k="counts.mcp_tools" /> tools: `biomcp`, which runs a BioMCP command, and `search` and `fetch`, which follow the shape ChatGPT research clients expect. The `biomcp` tool is not read-only: over stdio it can download [bundles](/local-data/), local copies of sources, and clean the store; [what the tool can change](#what-the-tool-can-change) lists the limits. This page adds the server to a client, or gives a shell agent the BioMCP skill instead.

## Requirements

- BioMCP installed. See [install](/getting-started/installation/).
- An MCP client: Claude Desktop, Claude Code, Codex, Cursor, Cline, VS Code or another client that starts stdio servers.

## Check the server answers

Restart the client and ask it to run a BioMCP command, such as "use biomcp to get gene BRAF". The client sends the command's words as the `args` array of the `biomcp` tool. This exchange starts the server over stdio and calls the tool the way a client does:

<Example id="mcp-call" />

The tool returns the same JSON reply, with the same [envelope](/results/), as the command line. MCP replies are always JSON; `--format md` has no effect there.

## What the tool can change

Over stdio, the `biomcp` tool runs the same commands as your shell, with your cache and your configuration. These commands change local state:

- `sync` downloads a bundle into the store.
- `store clean` removes expired local state and older cache files.
- `--fresh` sends a request again in place of a cached reply.
- Saving commands, such as `article text --save`, write new files. They never replace an existing file over MCP.

Over HTTP, the server refuses `sync`, `store clean`, `--fresh` and file saves. Over both, the tool refuses the `key` commands, so an agent cannot read, set or remove your keys. This exchange calls `store clean`, `sync hgnc` and `key list` over stdio, then over HTTP:

<Example id="mcp-writes" />

A refused call returns status `usage` with error code `usage.arguments`. The `search` and `fetch` tools only read; the [MCP tools reference](/reference/mcp-server/) shows their `readOnlyHint` annotations.

## Use search and fetch from ChatGPT-style clients

Research clients that expect `search` and `fetch` tools can use those two. `search` takes an [entity](/reference/entities/), the kind of record, and its arguments, such as `gene BRAF --limit 2`, or plain article text. Each result has an `id` that `fetch` accepts.

<Example id="mcp-search-tool" />

Rows without an exact record to fetch stay available through the `biomcp` tool.

BioMCP ships no connection steps for ChatGPT, and none were run for this page. BioMCP provides the `search` and `fetch` tools and an HTTP server. [OpenAI's MCP documentation](https://developers.openai.com/api/docs/mcp) says ChatGPT adds a custom MCP server by its remote URL. BioMCP's HTTP server does not authenticate callers, so a public URL needs a reverse proxy that does; see [run as a server](/getting-started/remote-http/).

## Install the desktop extension

The `.mcpb` desktop extension bundles the executable for macOS (x86_64 or arm64) or Windows (x86_64) and starts it with `serve`. There is no Linux `.mcpb`; on Linux, add the server with `biomcp mcp-config` as above. Open the downloaded `.mcpb` file with Claude Desktop to install it. The extension declares the same three tools.

## Give a shell agent the skill

An agent that runs shell commands can use the `biomcp` command directly. The skill teaches it the grammar and <Fact k="counts.use_cases" /> worked examples. `biomcp skill install DIR` writes the skill under `DIR/skills/biomcp`:

Point the directory at your agent's skills folder, such as `~/.claude`. Existing files stay unchanged unless you add `--force`. `biomcp skill status DIR` reports whether the installed copy matches this executable. `biomcp skill render` prints the guide, and `biomcp skill list` lists the worked examples:

## Run the server over HTTP

Clients that connect over HTTP use `biomcp serve --http`. HTTP refuses the commands that change local state, as [above](#what-the-tool-can-change). [Run as a server](/getting-started/remote-http/) covers addresses, allowed hosts and the health check.

## If the client shows no tools

- Run `<command path> version` in a shell, with the `command` path from the configuration. It prints `biomcp` and the version, <Fact k="version" />.
- Restart the client after changing its configuration.
- When the client starts with a different environment, a proxy or certificate set in your shell may be missing. Put `proxy` and `ca_bundle` in `config.json`; see [keys and configuration](/getting-started/api-keys/).

More failures are on [troubleshooting](/troubleshooting/). The tool schemas are in the [MCP tools reference](/reference/mcp-server/).
