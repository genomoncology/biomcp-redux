A project that used BioMCP won St. Jude Children's Research Hospital's KIDS BioHackathon in autumn 2025. Their data science office then invited me to speak to their community of practice, on October 24, 2025. The talk is an introduction to biomedical agents for researchers who had watched a colleague use one to win something. It assumes no background in agents.

[Watch the talk on YouTube](https://www.youtube.com/watch?v=lXoe-4TENDE). A transcript with chapter links is on [my site](https://www.imaurer.com/talks/biomcp-st-jude/).

## What it covers

The first half is orientation: pre-training, prompting, retrieval, post-training and the reasoning models of that year. The argument underneath is simple. A model answering from memory guesses. A model that can retrieve evidence and call tools does better work, and in biomedicine that difference decides whether an answer is usable.

The second half runs BioMCP against real sources: trial search on ClinicalTrials.gov, literature through PubTator, and variant lookups across genomic databases.

Two ideas have held up.

**Curated knowledge and language models fix each other's weaknesses.** A knowledge graph gives provenance, structure and an explanation you can trace. A language model gives flexible language and synthesis. Neither is enough alone.

**Tool output is part of the security boundary.** An untrusted server, or untrusted content returned through a trusted one, can steer a model. Turning on a tool is a decision about what counts as evidence.

## The prediction

At [54:46](https://www.youtube.com/watch?v=lXoe-4TENDE&t=3286s) I said:

> That CLI might actually be the new MCP.

I had built the command line mostly to test the server without driving MCP tools, then noticed agents used it more comfortably than the protocol. BioMCP 1.0 is built on that idea. The MCP server offers <Fact k="counts.mcp_tools" /> tools: <Fact k="mcp_tools" />. An agent learns one grammar. [How BioMCP works](/concepts/progressive-disclosure/) explains it.

## What is dated

The model names, prices and benchmark charts in the talk are a time capsule. The talk describes a Python library with many tools; BioMCP 1.0 is one executable with one grammar. Skills had shipped eight days before the talk, and BioMCP now embeds one. The parts about interfaces, evidence boundaries and validation still hold.
