By the end of this page you will have searched for the BRAF gene with BioMCP <Fact k="version" />, fetched its record, asked for one section, and checked which sources answered. It takes about five minutes. Every command here is free and needs no key.

## Before you start

You need a shell and a network connection. The examples filter JSON with `jq`; install it from your package manager, or add `--format md` to any command and read Markdown instead.

## 1. Install

<InstallLine />

Check that the command runs:

<Example id="version" />

If your shell says `command not found`, see [install](/install/#if-the-command-is-not-found).

## 2. Search

Every search starts with `biomcp search` and an entity. Search for genes named BRAF and ask for Markdown:

<Example id="qs-search-gene" />

The reply has four parts. **Next** lists commands to run after this one. **Query** echoes what you asked. **Result** holds the rows. **Sources** names each source, its terms and its state. Here HGNC answered with state `ok`.

## 3. Get one record

`biomcp get` fetches one record by its name or identifier. JSON is the default output, so this command uses `jq` to show the gene and the source outcomes:

<Example id="qs-get-gene" />

Read the `sources` list before the record. HGNC and MyGene.info answered. OncoKB was `skipped` with reason `no_key`, because OncoKB needs your own key. The reply is still `complete`: a skipped source is reported, never hidden.

## 4. Ask for a section

A record comes back small. Add a section word after the identifier to get more. The `constraint` section reads gnomAD's population constraint for the gene:

<Example id="qs-section" />

The [get gene reference](/reference/commands/get-gene/) lists every section word. You do not need to memorize them. Each reply's `next` list names the commands that fetch them:

<Example id="qs-next" />

An agent can run those `args` as they are. That is how BioMCP keeps replies short and lets the caller ask for more.

## Check that it worked

You succeeded when:

- `biomcp version` prints <Fact k="product" /> <Fact k="version" />.
- `biomcp get gene BRAF` returns `"status": "complete"` and HGNC with state `ok`.
- A section word returns that section with state `data`.

## Two common failures

A command without its required input stops with a usage error and exit code 2:

<Example id="qs-usage-error" />

Check the command's arguments with `biomcp help get gene` or on its [reference page](/reference/commands/get-gene/).

An identifier no source knows returns status `absent` and exit code 1:

<Example id="qs-absent" />

Absent means the sources returned no matching record for that input. It does not prove the thing does not exist. [Results](/results/) explains each status.

## Try one change

Replace `BRAF` with `KRAS` in step 3 and predict the HGNC identifier format before you run it. Then add the `pathways` section word.
