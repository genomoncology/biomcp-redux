BioMCP <Fact k="version" /> keeps two kinds of local data. Bundles are whole downloads of a source, such as HGNC or DDInter, that commands read locally. The cache holds recent replies so a repeated command answers without a request. Both live in the store in your cache folder, `~/.cache/biomcp/` on Linux.

## Which sources use bundles

| Bundle | Sync command | Synchronizes during a read? |
| --- | --- | --- |
| HGNC | `biomcp sync hgnc` | Yes, when missing or stale and at most 32 MiB |
| ClinGen gene validity and dosage | `biomcp sync clingen` | Yes, when missing or stale and at most 32 MiB |
| WikiPathways | `biomcp sync wikipathways` | No |
| cBioPortal studies | `biomcp sync cbioportal-studies` | No |
| EMA medicines | `biomcp sync ema` | No |
| DDInter | `biomcp sync ddinter` | No |
| WHO finished products | `biomcp sync who-pq` | No |
| WHO diagnostics | `biomcp sync who-ivd` | No |
| NCBI Genetic Testing Registry | `biomcp sync gtr` | No |
| FDA companion diagnostics list | `biomcp sync fda-cdx` | No |

A read synchronizes HGNC or ClinGen itself when the bundle is missing or stale and its download is at most 32 MiB (33,554,432 bytes). A larger download stops, and the source reports state `syncing`; run `biomcp sync` for that bundle. The limit is fixed in this release, and `config.json` has no setting for it. Every other bundle needs its sync command before the first read.

## 1. Synchronize a bundle

<Example id="sync-fda-cdx" />

The reply gives the rows and bytes stored. A sync replaces the whole bundle at once. A failed sync keeps the last usable copy. A command that needs a missing bundle fails and returns the sync command in `next`, with kind `sync`; [studies and cell lines](/studies-and-cell-lines/#4-search-cancer-studies) shows one.

When a bundle is older than its source, reads still answer from it. The source's state is `stale` instead of `ok`, so you can tell.

## 2. Work offline

`--offline` sends no request. Bundles and cached replies still answer. A source that would need the network reports `failed` with reason `offline`:

The first command answered from the HGNC bundle and a cached MyGene.info reply. The trial search had no cached reply, so its only source failed, its status is `failed`, and BioMCP exits with code 4. Offline mode never synchronizes a bundle.

## 3. Force a fresh request

`--fresh` skips cached replies and asks the source again. Use it when you know the source changed since your last run. The HTTP server refuses `--fresh`.

## 4. Clean the store

`biomcp store clean` removes expired replies, pools and snapshots, and cache files from older versions. Bundles and fresh entries stay.

Each count is what this run removed. The HTTP server refuses `store clean` and `sync`.

## Verify

`biomcp sync fda-cdx` returns status `complete` with a row count, and `biomcp --offline get gene BRAF` answers after one online run.

## If a sync fails

The reply names the source with state `failed` and a reason. `rejected` or `proxy` usually means a network rule blocks the download host; see [troubleshooting](/troubleshooting/). The previous bundle, if any, stays in use.
