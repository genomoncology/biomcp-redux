BioMCP <Fact k="version" /> is a command line tool and MCP server for biomedical data from public sources. A usage error usually identifies a command or argument problem. ClinicalTrials.gov can also reject a continuation request and produce this status after a source request. The reply identifies its [error schema](/reference/schemas/biomcp-error-4/), has `status` `usage`, an `error.code` and exit code 2. Find the code you see in a heading below; each entry gives the cause, the fix and how to confirm it.

<span id="usagearguments-expected-a-supported-command-with-checked-arguments"></span>

## usage.arguments: a missing or invalid argument

<Example id="qs-usage-error" />

**Cause.** A required argument is missing, a value is outside its choices or limits, or an option does not belong to this command. Exit code 2. When available, `error.option` identifies the argument and `error.valid_values` lists accepted values or forms.

**Fix.** Compare your command with `biomcp help search trial` (put your command's words after `help`) or its page in the [command reference](/reference/commands/). Check that the identifier comes before [section words](/concepts/progressive-disclosure/) and that `--source` names a source the command lists.

When `error.option` is `--next-page` for a ClinicalTrials.gov search, BioMCP either could not verify the continuation against its saved position and filters, or the registry rejected the request. In the CLI or stdio MCP, run the suggested `next` command to refresh the first page with the same search filters. Follow the new reply's page command unchanged.

**Confirm.** The command returns a reply with a `status` other than `usage`.

## usage.unknown_command: an unknown or dropped command

<Example id="ts-unknown-command" />

**Cause.** A word does not identify a supported command, such as a misspelling or a command dropped since 0.9. This can happen at the root or under an existing command, such as `search all`. Exit code 2. The reply's `next` list suggests help for the relevant command.

**Fix.** Run `biomcp help` for the command list. [Upgrading from 0.9](/upgrade-from-0-9/) maps old commands to new ones.

**Confirm.** The corrected command returns a reply with a `status` other than `usage`.

<span id="biomcp-biomcp---help-or-biomcp--h"></span>

## Show help

<Example id="ts-help" />

`biomcp`, `biomcp --help` and `biomcp -h` return help with status `complete` and exit code 0. `biomcp help` lists the command groups, and `biomcp help get gene` describes one command. The [command reference](/reference/commands/) has the complete generated reference.

**Confirm.** `biomcp help get gene` returns status `complete`.

## usage.retired: retired; use: ...

<Example id="ts-retired" />

**Cause.** An option or section from 0.9 that 1.0 retired or renamed.

**Fix.** The message names the replacement. Here `--variant` replaces `--mutation`.
