# BioMCP

A clean rebuild of BioMCP on the biodata layer. When it is ready, its history replaces the biomcp repository's, keeping that repository's stars and releases.

`make landing-gate` runs formatting, lint, dependency policy and separate instrumented case and library test suites. `make test` runs the ordinary suite for development. The coverage floor counts command cases, including CLI and MCP child processes, plus reviewed public type-contract targets explicitly owned in `sdlc/features.md`. Each listed target supplies its required Cargo features. Command-only coverage prints separately for historical comparison. Unlisted contract targets and library unit tests run in an excluded collection and never raise the counted figure. The denominator contains product Rust source; test targets, internal test modules, generated output and build scripts are excluded.

The build machine needs `cargo-llvm-cov` and the pinned toolchain's LLVM tools. `make coverage` follows the [external-test sequence](https://github.com/taiki-e/cargo-llvm-cov#get-coverage-of-external-tests) and prints each collection separately. The floor lives in `coverage.floor`; the threshold allows the architecture's counting tolerance. Raise an established floor only after reviewing the counted coverage. A failed suite has no complete coverage result.

`make unreached` lists missing lines from the existing profiles without rerunning tests. `sh scripts/coverage.sh report` repeats only the concise floor check. These commands require profiles from a successful coverage run in the same checkout. Full reports remain separate from the routine gate.

Every response source outcome includes its use category, publisher terms name and terms page, including skipped and failed outcomes. `biomcp health` prints the implemented sources, publisher terms, enabled state and bounded source reachability. It reports missing keys and disabled sources as skipped. It does not synchronize local bundles. `--disable-sources pubmed,restricted` disables individual source names or the `restricted` and `noncommercial` groups. The same setting lives in the JSON configuration as `"disable_sources": ["pubmed", "restricted"]`. Configuration and command settings combine by union; a command cannot enable a source disabled by configuration. Disabled sources cannot supply cached replies or restore stored article pools. Publisher terms remain authoritative, and the source category grants no rights in individual records.

BioMCP uses platform TLS trust roots. To add a company certificate authority, set `ca_bundle` in the config file to a PEM file. This adds certificates for every source and keeps verification enabled. `biomcp help network ca_bundle` explains this setting.

Set `proxy` in the config file to an HTTP or HTTPS proxy URL to use that route for every source. Otherwise BioMCP reads `HTTPS_PROXY`, `HTTP_PROXY` and `NO_PROXY`. Each proxy variable applies to its own scheme. `NO_PROXY` accepts comma-separated exact hosts or IPs, `.domain`, `*.domain`, optional ports, and `*`. An explicit config proxy overrides these environment settings. `biomcp help network proxy` explains routing.

Use `--format md` for a Markdown document with tables and copyable next commands. Set `"format": "md"` in the config file to use Markdown by default. `--format json` overrides that setting. MCP always returns JSON.
`make release-artifacts` checks release artifacts locally. It builds local wheels, binary archives, a local Homebrew formula and container images. It installs the candidate outside the checkout and checks embedded assets, the MCP lifecycle, replay and concurrent processes sharing an ordinary cache. It publishes nothing. The wheel inspector binds the installed binary to Cargo's profile and candidate bytes. Linux builds execute inside the declared manylinux floor and inspect ELF version requirements before writing wheel tags. Both container architectures execute. Missing native platform or Homebrew execution remains a release rehearsal requirement; the gate never labels it passed. Windows execution requires a Windows machine. Native platform execution and installed HTTP checks run in the installed-platform rehearsal described in [the release plan](sdlc/planning/release.md).

The desktop extension and MCP registry templates keep their existing channel names. The local producer supplies their version from Cargo, bundles only the matching platform's executable, and writes registry metadata that selects the local `biomcp-cli` wheel and `serve` entry point. The gate installs each bundle in a fresh directory and starts its manifest command. It installs the registry-selected wheel in a separate environment with a standard offline wheel installer and starts its declared command. It does not contact a desktop client or publish to the registry.

The wheel exposes `biomcp` and the registry's package entry point, `biomcp-cli`, from the same candidate bytes. Registry-selected invocation therefore works after a normal offline package installation. Registry metadata follows the [official package schema](https://static.modelcontextprotocol.io/schemas/2025-12-11/server.schema.json); desktop bundle installation follows the [MCPB manifest command rules](https://github.com/modelcontextprotocol/mcpb/blob/main/MANIFEST.md).

`biomcp serve --http` serves native MCP clients at `http://127.0.0.1:8080/mcp`. Supply an address after `--http` to choose another listener. A non-loopback address requires repeatable `--allow-host HOST` values or `"http": {"allowed_hosts": ["biomcp.example"]}` in the configuration file. Hostnames are exact and case-insensitive; an explicit port restricts that authority. Browser Origin is refused and forwarding headers do not grant access. The Host allowlist and `--allow-host` do not authenticate callers. Any peer that can reach the listener can send an allowed Host header. Restrict listener access to trusted clients. HTTP MCP refuses `sync`, `store clean` and `--fresh` with a usage error before provider requests or storage changes. Bearer-token authentication is deferred.

Research clients can call the read-only MCP tools `search` and `fetch` beside `biomcp`. Search accepts article query text or an explicit entity followed by its CLI arguments, such as `trial --condition melanoma`. Copy a result's opaque `id` into fetch to read the same bounded CLI record as Markdown. Metadata retains the full CLI envelope, including source terms and problems. Uncitable rows remain in search metadata and are available through `biomcp`. An absent or ambiguous fetch returns the unchanged CLI envelope as a tool error. The main tool accepts CLI commands under its transport restrictions.

The HTTP endpoint returns one JSON object per MCP request and supports revisions 2025-11-25 and 2026-07-28. Modern clients must send matching protocol version, method and tool-name headers as the [Streamable HTTP specification](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http) requires. It accepts bounded Content-Length and chunked bodies. `GET /health` reports the executable version and local store availability with HTTP 200 or 503. This endpoint makes no upstream requests. The server writes its selected listener address to stderr when it starts. Ctrl-C stops admission and waits for admitted requests to finish within their existing deadlines.

Use `article text ID --save PATH` to save the complete JATS Markdown document with its title, identifiers, license and source. A folder destination gets `ID.md`. Use `article supplement ID FILE --save PATH` to save the original source bytes, including files the row reader marks unsupported. A folder destination keeps the source filename. Both commands return the absolute path, byte count, SHA-256, license and source URL; text also reports its part count. CLI saves require `--replace` for existing files. Stdio MCP allows new-file saves and refuses `--save` with `--replace` before provider requests or file changes. HTTP server calls refuse saves. CLI and stdio MCP saves belong to the caller and create no download directory or saved-file registry.

Use `get trial NCT… references` for registry publication identities, native reference types and a next command to retrieve their article cards. Use `get trial NCT… documents` to inspect the posted document manifest. `trial document NCT… FILE --save PATH` saves only an exact listed filename under the same explicit save rule. The reply preserves the source URL, document metadata and license without granting reuse rights. Documents are downloaded as bounded PDF bytes and never read as text.

Use `get variant ID civic` to read CIViC molecular profiles and follow their separate evidence and assertion pages. A checked member match preserves the full compound profile and its source claim context. Name matches remain candidates. Claims that the common model cannot represent retain their native facts. Use `get variant ID hotspots` for source transcript, residue and alternate counts. Rows marked `candidate` with `no_join_id` have no established transcript and consequence join to the requested variant. These residue counts do not state an allele frequency or clinical actionability. Cancer Hotspots data reuse terms remain unverified.
Use `variant normalize --source car|mutalyzer|variantvalidator|all --hgvs TEXT` to send a reference-qualified description unchanged to a named service. VariantValidator and `all` require `--build GRCh37|GRCh38`. Each service keeps its own outcome, source mappings, messages and available version metadata. A provider validation warning can reject an HTTP 200 reply. `all` returns independent results and never chooses a transcript or consensus. Mapping and message pages use `--limit` and `--offset`; typed next commands keep the remaining rows reachable.
Use `search variant --gene EGFR --protein L858R` for an explicit gene and checked amino-acid substitution. Use `--region chr7:55259515-55259515 --build GRCh37` for MyVariant's one-based inclusive regional syntax, or `--query TEXT --source myvariant` for unchanged source query text. Gene and protein values are escaped as source literals. The reply echoes the exact source query and assembly and keeps native candidate order and totals. Protein and raw searches send no assembly unless `--build` supplies one. Returned coordinates retain only the assembly stated by the source. Page actions retain every selector; a warm page uses the ordinary checked cache. Broad queries disclose the command's result-window bound. No candidate becomes a chosen allele.

Use `variant recurrence CA… --source cbioportal --gene SYMBOL --study ID --profile ID --sample-set ID` to inspect exact genomic allele observations in an explicit cohort. `--limit` bounds source mutation rows and `--page` selects the native page. The result counts distinct matched samples on that page. `selected_sample_count` is the source sample-list size and supplies no assayed denominator. The source may omit that count from its summary metadata. Missing genome builds and uncertain insertion or deletion representations remain problems. The reply preserves study metadata and flags study-specific reuse terms as unverified. Follow its page command to inspect more rows.

Use `get variant ID cosmic` to inspect the historical COSMIC fragments MyVariant carries. Each fragment names its MyVariant parent record, preserves the component's original spellings and reports its identity as unverified. The reply shows the snapshot version, source upload date, source warning and component terms. It does not establish that the fragment and parent describe the same allele. Source frequencies retain their published values without inferred units or denominators.

`get variant ID predict` and `get variant ID conservation` preserve source measurements, native labels, context arrays, component versions and publisher terms. Every component is on by default. Commercial users should set `"disable_sources": ["noncommercial", "restricted"]` in the configuration file. The same groups work with `--disable-sources`. Groups switch off matching component fields while other aggregator fields remain available. Naming `myvariant` switches off the entire service. These settings apply before requests and prevent disabled values from returning through cached replies or replay. Public API access grants no additional component rights. The retired `predictions` spelling names `predict` as its replacement.
Use `get variant clinvar:128042 clinvar` or `get variant CA000434 erepo` for source-native assertions. Use `variant assertions CA000434 --source erepo` to page source rows independently. Select a native assertion ID and version to inspect its source details. Source-local absence does not establish allele absence. Selected historical records include an exact version link and compact native assessments. A conflict flag preserves disagreements between source outcome labels and identifiers; the original nested evidence remains behind the source link.


Use `get variant CA123643 population` for source population counts and `variant population CA123643 --detail` for a bounded ancestry page. The population join requires one source-given GRCh38 single-nucleotide allele. Missing or ambiguous join information produces a problem before gnomAD is called. Exome and genome records remain independent. The source selector does not establish a dataset release. Each request also asks for the source VA cohort release and counts. A typed population-frequency record requires that same response to supply a release for the matching total cohort and matching allele counts. Replies preserve native counts and report a problem when the release is missing or the counts disagree. A missing dataset stays absent; a reported zero stays zero. BioMCP does not compute a frequency from counts or sum overlapping ancestry and sex groups.

Use `get variant rs113488022 gwas` for current GWAS Catalog v2 associations. An exact rsID needs no allele-resolution request. Association pages retain the source study, trait and effect allele with the source's effect estimates. An empty result means the catalog returned no associations for that request. It supplies no clinical classification. Named source sections use `--section-limit` and `--section-offset` independently of identity candidate paging.

`make nightly-live-check` runs the public live diagnostic once. Set `BIOMCP_EVIDENCE_HOST`, `BIOMCP_EVIDENCE_DIR` and `BIOMCP_SCRATCH_DIR` to the evidence host, remote evidence directory and local scratch directory. The script also accepts `--host`, `--evidence-dir` and `--scratch-dir`. It keeps each run outside the checkout and temporary directory, then transfers its report, build log, runner exit status and revision to the explicit evidence host and directory. It verifies the transferred manifest and file hashes before removing its own scratch. The delivered report adds a classification version, one classification per checked case and separate healthy, churn, throttled, uncertain and failure counts. Successful discovery changes clear dependent request drift only when the complete received identifiers account for the changed request inputs. Churn and exhausted 429 responses alone do not fail the run. Equivalent-request invariants, schema defects, unexpected statuses, reported errors, incomplete evidence, malformed reports, runner failures and failed evidence transfers return failure. Failed transfers retain scratch and print its location. The command does not install a schedule or retry the whole run. Drifted and errored cases retain credential-free request URLs, statuses, response shapes, result identities and baseline/live product context in that report. Cases without drift retain summaries. The diagnostic bounds the total serialized witness payload with `MAX_WITNESS_BYTES` and records an explicit cut when it cannot retain a case. Only open-source product values are retained; other source terms keep shape and identities. Headers and raw provider bodies are never retained.
