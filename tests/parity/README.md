# Recorded parity selections

Run `make parity-run PLAN=tests/parity/sample.json BASELINE=/absolute/biomcp OUT=/absolute/new-directory` with the released 0.9.3 executable. The command prints one summary and retains a JSON report, each command's complete stdout and stderr, byte counts and elapsed microseconds. It records executable hashes and keeps source provenance beside the raw output. The output directory must be new. Use a directory outside Git for retained evidence.

A plan selects harvested case steps. Each entry declares the old command, its parity spelling table, old global options, source routes and fact projections. `facts` maps current assertion pointers to released JSON pointers. Values and assertion operators come directly from the harvested case. Omit `assertion_pointers` to assess every assertion in the selected step. An explicit list bounds a sample; the report lists unselected assertion pointers. Missing projections produce assessment gaps on both sides and a nonzero exit. An assertion the old binary gets right and the new binary gets wrong also produces a nonzero exit. A plan declares the exact expected baseline exit and JSON stream. Unexpected exits or malformed JSON produce assessment gaps; a reviewed error-envelope fact can be compared at its declared exit.

Source routes name existing replay capture files and a source from the pinned released registry. Each route must match that source's reviewed endpoint variable and native host. The runner rejects an unknown endpoint or host before either binary runs. It creates one local HTTP peer per enabled baseline source and points its declared endpoint variable at that peer. It disables every other source from the exact released registry. The runner emits one derived `--disable-sources` flag and rejects that flag in plan globals. The old child has an empty inherited environment. The released client ignores system proxies, so the baseline uses explicit endpoint overrides. No peer opens a provider connection or falls back to a live source. The new child uses the case runner's offline replay transport and an independent rejecting proxy guard. Routes select one retained exchange explicitly when a capture contains several. The local peer preserves its HTTP status, content type and JSON or text body. Recorded latency below the existing ten-second peer bound is preserved, including timeout scenarios. Sidecar bodies and delays outside that bound remain explicit recording gaps. An optional `envelope` wraps that unchanged value under one named JSON property. An optional `count_field` supplies the recorded array length as required decoder metadata. This count describes the replay array and makes no claim about a live source total. Other endpoint declarations require reviewed released-source provenance. Secrets are never inherited.

`released-sources.json` retains the exact public registry from release source revision `5641de7d7b79b53872f8599dbb4dba22e611dcaf`. `released-endpoints.json` owns the endpoint declarations from that revision. Each endpoint variable has one declaration, its native URL and the exact released constants. Source bindings keep released IDs separate from recording spellings. Sources with fixed URLs and no reviewed override have an explicit isolation reason and cannot be enabled through an undeclared route. Every endpoint of an enabled source gets a local peer. Endpoints without routes reject all requests. The route source ID and capture source ID remain separate publisher spellings. Unreviewed endpoint mappings are explicit isolation gaps, and the runner refuses them before launching commands.

The sample takes the full-summary assertion from `gene/braf.yaml`. The gene spelling table maps `gene definition` to `get gene`. Released 0.9.3 issues a MyGene symbol query and expects an object with a `hits` array. The current binary issues a MyGene batch POST and consumes an array directly. The sample supplies that recorded batch array unchanged under `hits` for the released request. The released decoder also requires `total`, so the route derives it from the recorded array length. It changes no source field or value. The evidence keeps the original capture, adapted body and received request. Open Targets is explicitly disabled because the sample assesses the MyGene summary alone. This is a check of summary retention across the two binaries, not a timing comparison of identical request plans.

The sample does not claim whole-case or whole-comparison success. The full run needs reviewed command routes and projections for the remaining harvested assertions. Missing mappings remain assessment gaps.

Run `python3 scripts/test_parity_runner.py /absolute/released-0.9.3 /absolute/new-evidence-root` for the scoped proof. It uses both actual executables, checks the generated verdicts against their retained raw outputs, verifies unchanged source values and checks that a missing projection cannot pass.

Run `make parity-inventory PLAN=tests/parity/inventory.json OUT=/absolute/new-report.json` to inspect the whole harvested set without launching either executable. It uses the case runner's YAML/YML discovery, parser, floor loader and assertion validator. The output contains one bounded summary; the report lists every case and its CLI, MCP, follow and walk surfaces. A direct plan must project every assertion or give a source-grounded per-fact unsupported reason, and must compare at least one fact. An absent or partial plan remains unclassified and makes the command fail. Trial and Pathway declarations are in separate batch files. Other direct families have explicit case-level pending ownership; these assessment gaps keep the whole inventory gate failing until their declarations land. Inventory success alone cannot serve as whole-comparison proof.

Cases with ordered steps, setup configuration, bundle or offline state, followed actions or walks require sequence execution. Inventory reuses reviewed direct declarations for matching commands, configuration, exits and captures in the current case. It names each unmatched step under `sequence_gap`. File format never exempts a case. A CLI/MCP pair within one step shares the case's assertions. An `inventory.covered` exception can name a distinct direct CLI case and map every assertion pointer; the validator checks identical command arguments, configuration and assertion values. A coverage target must itself have a complete direct plan. An `inventory.unprojectable` exception must name the precise unsupported question, its reason and the released source path. These exceptions describe released semantics and must be reviewed against that release; missing runner support is an assessment gap.

Sequence selections keep independent candidate and released environments across all ordered case steps. Candidate execution uses the case runner's shared follow and walk navigator. Baseline questions remain direct released commands. Each step retains its CLI outputs and MCP frames. A followed step declares its reviewed `candidate_command`; each walk continuation declares a candidate command, released command and routes under `pages`. `baseline_items` names the released array to concatenate. Every assertion needs a projection or a source-grounded unsupported reason. An explicit `baseline_gap` reports missing recordings or safe transport separately from a missing released command. A `stored_only` released read enables its declared sources while every source peer rejects requests.

An empty `steps` list selects declaration reuse for a named sequence case. Reuse binds routes to captures present in that case's replay directory. A missing complete mapping refuses execution and remains a named inventory gap. Bounded witness selections are in `sequences.json`; they do not declare the rest of the corpus executable. Route `exchange_order` selects increasing exchange ordinals for repeated requests within a command. It cannot combine with the single `exchange` selector. The peer consumes the declared replies in order and refuses requests after exhaustion.

Run `python3 scripts/test_parity_sequences.py /absolute/released-0.9.3 /absolute/new-evidence-root` for the bounded sequence proof. It checks actual raw output, followed actions, native walks, YAML-form input, shared Study and Drug state, both missing WikiPathways states and ordered retained exchanges. Released DDInter synchronization has fixed download URLs; its synthetic interaction questions also require an absent MyChem identity recording. Released UniProt continuation headers need a confined adapter. These cases retain baseline assessment gaps. Released Study metadata questions have no equivalent command or matching Datahub input. Their unsupported steps remain visible while the candidate runs its complete sync sequence.

Closed projections support a released pointer, a declared identity object whose members are strings or a named source spelling, and the length of an actual selected array. Missing, null, unknown source spellings and wrong types are assessment gaps. The pathway identity source comes from the released source field. No expected fact supplies an identity value. Reports retain each raw output, declared component pointers and the actual projected value.

Search routes bind exact decoded question query selectors and allow unrelated pagination or field-order differences. Duplicate bound query keys, missing selectors and mismatched values reject delivery. Command selectors additionally preserve harvested client-side options, including the released age filter.

Run `python3 scripts/test_parity_batches.py /absolute/released-0.9.3 /absolute/new-evidence-root` for the bounded Trial and Pathway proof. It retains the whole dry inventory with named pending families, positive cases, deliberate wrong projections, a native malformed section response with exact baseline and candidate exits, and rejection witnesses for query mismatch, identity type and omitted age. Released pathway search constructs a WikiPathways client before it can query Reactome. The retained Reactome-only failure captures lack that required source input. Their provider-name projections remain declared from released error serialization, but execution reports an explicit recording assessment gap. This batch does not prove a successful nonzero released error-envelope comparison; the selected section-error witness compares the actual retained provider name at released exit zero.

Variant delivery review uses the pinned released source. Mutalyzer and VariantValidator build escaped normalization paths under their configured bases. ERepo builds summary, gene, detail and guideline paths under its configured base; its source URLs remain output fields. GWAS sends both ordinary and decoder-retry requests through its configured base. MyVariant sends query and variant lookup plans through its configured base. These clients never fetch response-provided URLs. `src/sources/mod.rs::request_from_plan` joins paths under those bases, and `ordinary_url_policy.rs::redirect_target_is_allowed` permits only the same origin. The released shared client ignores system proxies. The local runner therefore confines these five sources to their declared local peers. ERepo pagination and legacy GWAS input still carry explicit recording gaps.

Indexing projections select the released `ArticleIndexing` object. They preserve native author order while concatenating affiliation text, count all affiliations before taking the current first-ten window, retain distinct nonmissing ORCIDs in encounter order, and rename MeSH descriptor/qualifier `text` and `major_topic` members to the current names. Empty native arrays stay empty; missing arrays and malformed members remain assessment gaps. The release schema and `article_indexing_from_citation` in `src/entities/article/mod.rs` and `detail.rs` supply these fields. The source body and the case assertions supply no projection constants. The article key projection chooses the retained PMID, PMCID, DOI or Semantic Scholar ID in that order. A key-only item requires empty released title and absent date/journal; it cannot erase a retained header.
