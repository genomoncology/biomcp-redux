# Trial recordings

The condition, biomarker, intervention, status, phase, combined-phase, study-type, sex, age-missing, distance, facility, eligibility, sponsor, funder, updated, until and results directories reuse unmodified ClinicalTrials.gov JSON responses from the trial investigation. Their exact original URLs, raw replies and checksums remain with its retained evidence. These snapshots report registry processing time `2026-10-23T09:00:04`.

A local TLS server accepted only the exact captured method, host, path and parameter map. The actual CLI generated each recording with `--record` in a new empty directory. The recording's fetch time measures local delivery. It does not establish a new public-source fetch or the original snapshot's retrieval time. The original JSON values were preserved; the transport owns request encoding, canonical URLs, hashes and envelopes.

The exact-conjunction, count-only and continuation requests were missing from the original investigation identities. The actual CLI recorded each once from the public source on 2026-10-24. The continuation response omits `totalCount`; the separate native count-only response supplies the total. The walk directory combines these unchanged transport recordings with the first-page snapshot.

ClinicalTrials.gov data are public registry data subject to the publisher's attribution and source-date terms. Text matching and structured filters support discovery. These cases make no clinical eligibility claim.

The gene query adds one actual public-source recording for `query.term=BRAF`. The CLI generated it with explicit discovery text. The gene case reuses the identical native request after the shared HGNC resolver returns the approved BRAF symbol. The existing checked HGNC fixture subset is copied unchanged; no new HGNC download was performed.

On 2026-11-11 the search request's `fields` list gained `LeadSponsorName`, `StartDate`, `StartDateType`, `PrimaryCompletionDate` and `PrimaryCompletionDateType`, so every search request has a new URL. The 102 earlier search recordings here and under `tests/replies/search/` and `tests/replies/grammar/` were re-keyed, not re-recorded: each file's `url` now carries the new list and its filename is the fetch layer's GET identity of that URL (SHA-256 of `GET`, a zero byte and the URL). No reply body changed by a byte. Those bodies therefore answer the old, shorter field list: their rows hold no sponsor or start and primary completion dates, which a live reply to the recorded URL would hold. The row-fields directory is the one search recording made after the change. The actual CLI recorded it from the public source on 2026-11-11 with `--record`, and it carries the three new values.
